# PI NEXT 0.10.0-beta.2（预发行）

> 0.10.0-beta.1 之后的 1 个提交：**补测**。上一版是「先提交、后验证」发出去的，这一版把验证
> 补上 —— 在独立 worktree、独立端口、独立 profile 的 headless Chrome 里读真 computed style
> 并逐像素采样，测出三个问题，**其中两个是 beta.1 自己引入的**，都在这里修掉。
> 顺带加了一条守卫，防同类问题再犯。

范围：`v0.10.0-beta.1..HEAD` —— **8 个文件，+167 / −10 行**，1 个提交。

## 修复

- **深色顶栏两条亮线**（beta.1 引入）。beta.1 给 `.d-topbar` 新加了 `box-shadow`，用的是浅色
  `--nx-glass-rim`，而 kit 的 `-dark` 三条定义了却**全仓零引用**。实测深色顶栏上下缘像素
  167 / 154，顶栏本身只有 78 —— 与用户最初报的「黑边」是同一类问题，只是明暗反了。
  现在在**令牌层**换一次，三个消费方（`.d-topbar` / `.d-jump` / PWA `.m-top-btn`）一起跟上；
  深色既不画 rim 也不画白色高光（近黑底上两者都读成亮线，换成白高光后 y=0 反而升到 212）。
- **暗色分隔线全没了**（beta.1 引入）。beta.1 追加在文件末尾的 `:root` 块把 `--nx-line`
  声明成了浅色值，而它与原 `[data-theme="dark"]` 同特异性（0-1-0）且在后 → 暗色原本的
  `rgba(255,255,255,.09)` 被静默盖掉，暗色下所有分隔线变成 10% 黑，在近黑底上等于没有。
  实测 `.d-side` 的 `border-right-color` 曾是 `rgba(0,0,0,0.1)`，现为 `rgba(255,255,255,0.1)`。
- **侧栏宽度**：beta.1 发行说明里的「侧栏 260 → 256」**不成立** —— 产品侧栏一直是 **280**，
  真值在 `lib/panel-layout.ts` 的 `SIDEBAR_DEFAULT_WIDTH`，当时改的两处 CSS 是**永不生效的
  兜底**。现在改真值（280 → 256，macOS kit 的侧栏实测值），旧 `tokens.css` §11 同改，三处同值。

## 新增

- **暗色令牌覆盖守卫**（`check-v5.mjs` §3c）：第一个暗色块之后被 `:root` 声明的**颜色类**
  令牌（值含 hex / rgb / hsl / color-mix / `-light-`），必须在它**之后**的某个暗色块里重新
  声明，否则 `npm run design:v5` 报错。尺寸类令牌（`--nx-c-*` / `--nx-fs-*`…）两主题同值，
  不在此列。守卫本身反向验证过：删掉修复，精确报出 web / pwa 两条。

## 1 · P0 · 会让人读错、看不见、或看起来像没做完

### 1.1 设置弹窗是半透明的，背后的正文穿透面板

**位置**：Web 设置弹窗全部页面；PWA 设置 hub 与二级页。

**证据（已做 A/B 对照，可复现）**
`proof/proof-ab-modal.png` —— **同一块弹窗区域**，上：压在密集正文上；下：压在空状态上。
上面那张里，会话正文（"token 这个词经常被当成…"）清清楚楚地叠在弹窗自己的标签「壁纸（默认外观）」「显示壁纸」「当前壁纸」上。

像素比对（`shots-settings2` vs `shots-empty-settings`，同一 crop 框）：

| 区域 | 随背景变化的像素 | 最大差值 |
|---|---|---|
| 弹窗面板内部 | **5.0%**（37,618 / 751,100） | 46 |
| 弹窗外会话区（对照） | 100%（背景确实换了） | 102 |

`proof/proof-diffmask.png` 是这张差分掩膜：弹窗区域内浮出的正是背后的品牌字标、四张空状态卡和正文段落。

**根因（不是"动画没播完"）**
`design/v5/base.css:220` `--nx-mat-thick-bg-light: #ffffffd9`（85% 白）挂在
`.settings-dialog-surface` / `.d-modal-box` / `.d-pop-float` / `.context-menu` 上（`app/fork-ui.css:3472`）。
而 `app/fork-ui.css:3464` 的注释写明了：**弹层刻意不给 `backdrop-filter`**——因为它会让弹层成为
`position: fixed` 后代的包含块，弹层里的浮窗会被裁掉（2026-10-08 的 Agents 浮窗事故）。
于是：**这套材质是按「半透明 + 模糊」设计的，模糊被技术性撤掉之后只剩半透明**，
背后还是锐利的正文，以约 15–20% 透出来，就变成可辨认的幽灵文字。

**修法（二选一）**
1. **推荐**：弹层面给**不透明底**（浅色 `#fff`、深色用对应层色），把「材质感」只留给不会当定位祖先的**面**（侧栏、输入区——那些地方背后本来也没有正文）。
2. 保留半透明但**恢复 blur** —— 前提是先解决 fixed 包含块：把弹层里的浮窗改成 portal。

**验收**：把设置弹窗叠在正文最密的那一段上截图，面板内不得出现任何可辨认的底字。

### 1.2 阅读区正文 13px / 行高 1.38 / 每行约 54–59 汉字

**位置**：Web 会话正文（`web/page-1440x900.png`、`proof/crop-chat-text.png`）。这是全产品**被读得最多**的一块。

**证据**
- 截图工具：「多行正文行高过紧 **7 处（1.38）**」「正文行太长 **6 处（每行约 59 字）**」
- 截图上量：正文列 x≈438→1140（约 700px），一行约 54 个汉字 → 字号约 13px

**根因**
`design/v5/web/system.css:275`

```css
.d-md { font-size: var(--nx-sk-t-body-size); line-height: var(--nx-sk-t-body-loose-lh); }
```

这两个值来自 **Apple macOS UI Kit**（`design/v5/sketch-macos.css:179,208` → 13px / 18px = **1.3846**）。
那是**控件标签**的规格，不是长文阅读的规格。

**对照：PWA 形态是对的。** `design/v5/pwa/system.css:83`

```css
.m-md { font-size: var(--nx-fs-body); line-height: var(--nx-lh-body); }   /* 17px / 1.60 */
```

手机上实测行距 27px / 17px = **1.59**，与 `--nx-lh-body` 一致。
所以**两套形态本来就是两套行高：PWA 1.60，Web 1.38 —— Web 是那个异类**，
而它替换用的值（Apple kit 的控件行高）跟这个位置要做的事没关系。

更值得记一笔的是：`design/v5/base.css:78` 为「长文阅读」专门定义了 `--nx-lh-reading: 1.75`，
**它在产品里一次都没被引用**（全仓 grep 只有已退役的 v1 `board.css` 在用）——是个死 token。
这正是 `LANDING.md` 反复警告的那类债：值有出处，但和画面没有关系。

**修法**
- `.d-md` 的 `line-height` 换成已有的 `--nx-lh-reading`（**不要新造值**）
- 正文列 `max-width: 44–48em`（13px 下约 570–620px ≈ 44 汉字/行），保持与现有左起点对齐
- **字号可以不动**（13px 对高密度工具合规），行高和行长必须动

**验收**：三行中文段落的行距一眼能数出来；正文块明显窄于「工具调用行」和输入框的整宽。

### 1.3 PWA 中文标签被挤成竖排断字

**位置与证据**
- 抽屉底栏「设置」→ **设 / 置**（`pwa/page.png`、`proof/crop-pwa-foot.png`）
- 设置 · 通用「宽度」→ **宽 / 度**（`pwa/page.png` 的 general 帧、`proof/crop-pwa-width.png`）

**关键点**：两处标签右边都还有**大片空白** —— 不是空间不够，是标签列宽被写死且没有 `nowrap`。
移动端最底一行出现竖排汉字，是最容易被当成「没做完」的破绽。

**修法**：标签列给 `min-width` + `white-space: nowrap`；抽屉页脚改成三个等分格（设置 · 快捷键 · 手机与推送）。
**验收**：390 宽下「设置」「宽度」都在一行内。

### 1.4 次级文字对比度集体不达标 —— 而项目自己的门禁现在是红的

**证据**：截图工具在运行中的界面上查到
- Web 主界面 **12 处**、设置 · 通用 **72 处**、设置 · MCP **54 处**
- PWA **7–46 处**
- 典型：侧栏分组名「项目」**1.84:1**（`proof/crop-sidebar-head.png`）、版本徽标 `v0.10.0-beta.2` **1.81:1**（`proof/crop-sidebar-foot.png`）、分段控件未选中「聊天」3.82:1、消息元信息「9.0s · 21k token」「0 次工具调用 · 1 段思考」

**另一件事**：`npm run check:contrast`（项目自己的门禁）**退出码 1**，4 项 FAIL：

```
[light] FAIL 3.52:1 (≥4.5) 主按钮文字 / 主按钮底
[light] FAIL 3.52:1 (≥4.5) accent 文字 / 画布
[light] FAIL 3.52:1 (≥4.5) accent 文字 / 侧栏
[dark]  FAIL 3.23:1 (≥4.5) 主按钮文字 / 主按钮底
```

而且 12 项检查里有 **6 项被 SKIP** —— 理由是「含 alpha，需先合成背景」。
被跳过的恰好是「正文 / 次要文字 / 辅助文字」这几档，也就是实际不达标的那几档。
**门禁有盲区，且现在是红的。**

**修法**
- 把 `--nx-text-2` / `--nx-text-3` 合成到实际背景后的对比度提到 **≥4.5:1**（分组名、元信息、卡片说明）；版本徽标不要灰底灰字
- 门禁改成「先把 alpha 合成到真实背景再算」，否则这几档永远查不到
- 主按钮/accent 文字 3.52:1：把 accent 底或按钮前景调到达标

**验收**：每类二级文字 ≥4.5:1；截图缩到 50% 仍能读出分组名。

## 2 · P1 · 信息丢失与层级问题

### 2.1 PWA 的 MCP 列表被降级成一串项目符号

`pwa/page.png`（MCP 帧）vs `web/page.png`（MCP 帧），`proof/crop-pwa-mcplist.png`：

| | 桌面 | 手机 |
|---|---|---|
| 每个服务器 | 名称 + `codemode` chip + 命令路径 + `stdio` + `不走 OAuth` + 启用开关 + ⋮ | `• tender` `• stitch` `• ios-simulator` `• android-emulator` |

外加一个英文分组词 `global`，卡片里还有大片死空白。
**用户在手机上回答不了「这个服务器开着吗」** —— 而这正是打开这一页的原因。

**修法**：手机每行至少留「启用开关 + 名称 + 传输/状态」，路径折叠进详情；`global` 改「全局」并与「项目」分成两个可见分组。

### 2.2 设置弹窗的信息层级是平的，且同一块三种叫法

`web/page.png`（通用帧）：分组标题（外观 / 主题皮肤 / 壁纸（默认外观）/ 侧边栏 / 界面字体）与行标题（显示壁纸 / 当前壁纸 / 半透明 / 宽度）**字号字重几乎一致**，全靠灰色小字和一堆分隔线撑层级；
同一块里出现「界面字体」「UI 字体」「UI 字号」三种叫法。

**修法**：分组标题固定用 `xl`/`title` 角色 + 更重字重；行标题降 `body`、行说明降 `xs`；统一成「界面字体 / 界面字号」。

### 2.3 主题皮肤条：选中卡的勾压住标题，默认皮肤预览是空灰方块

`proof/crop-skins.png`：`✓` 角标压在「默认皮肤」标签上；默认皮肤那张卡是一片空灰，看起来像图没加载出来。

**修法**：选中态改成描边 + 角标勾；默认皮肤补真实缩略图或明确的「无壁纸」图形。

### 2.4 PWA「导入 / 导出 / 编辑」三个全宽堆叠按钮

`pwa/page.png`（general 帧）vs `web/page.png`（通用帧）同位置是三个并排小按钮。
三个**次要**动作各自占满一行，视觉重量与「新建任务」同级，把「外观」这一屏拉得很长。

**修法**：收成一行三个紧凑按钮；或「编辑」为主，导入/导出进 ⋯。全宽只留给真正的主操作。

### 2.5 桌面弹窗右上角有个孤立的「关闭」小字

`web/page.png`（通用帧）x≈1203 / y≈139：与 `✕` 不同行、对比度 <2:1，像是把无障碍文案渲染到了画面上。
**修法**：只留 `✕` + `aria-label`。

## 3 · P2 · 小问题（合成一段）

- 空状态四张卡右下角的 **⚡** 语义不明（无文字；与卡片本体是两个可点区还是同一个动作，静态帧分不出）
- 空状态副标题「在下面输入第一条消息开始会话：@ 引用上下文，/ 调命令。」—— 中文句读里夹了孤立的半角符号
- 抽屉每行的 `⋯` / `+` 无文字，触屏没有 hover 兜底
- 桌面侧栏宽度写 `256 px`，手机只写 `256`（单位丢失）
- 顶栏会话标题与正文左起点不对齐（正文从 x=440 起）
- 「0 次工具调用」为 0 时仍占一行
- PWA 搜索占位写「搜索所有对话…」，但下面列的是项目
- 可直接删的文字：「壁纸（默认外观）」的括号注释
- MCP 页那句 `4 个服务器 · 4 个启用 · 配置文件 ~/.pi/agent/mcp.json 与项目 .pi/mcp.json`：一句话里混了计数、状态和两个路径，且末字被裁（`proof/crop-mcp-row.png`）

## 4 · 两套形态之间（Web vs PWA）

1. **同一段正文，行高两套**：Web **1.38**（`--nx-sk-t-body-loose-lh`，Apple kit 控件规格）/ PWA **1.60**（`--nx-lh-body`，实测 1.59）。
   两套本来就该是两套值，但**两边的值都不是为「读」选的**。阅读区是硬门槛，**两套都统一到 `--nx-lh-reading` 1.75**。
2. **MCP 行的信息落差最大**（见 2.1）。
3. **手机把下拉换成分段按钮**（自动 / 始终开启、直接调用 / 脚本调用）—— 这是**合理的移动适配，保留**；但两边选项文案必须逐字一致。
4. **手机抽屉底栏保留了桌面语义**：`⌘`（触屏没有对应物）+ 手机图标 + 1.67:1 的版本徽标，一起跟在被挤成两行的「设置」后面。
5. **说明文字的多少是反的**：手机设置 hub 每张卡都带一行说明，桌面左导航一条都没有 —— 但手机那层说明对比度太低读不到，桌面那层又完全没有，两边都没处理好。

## 5 · 保留（修改时不要磨掉）

- **两套类前缀换来的真适配**：手机把桌面左导航换成「图标 + 标题 + 一行说明 + 需项目徽章 + 箭头」的分组卡片，把下拉换成分段按钮。这是这个产品有辨识度的地方，**不要为了「两套形态一致」把它们改回桌面控件**。
- **空状态那四张任务卡**（了解这个项目 / 审查当前改动 / 补测试覆盖 / 讲清核心流程），以及把 `@ 引用上下文`、`/ 调命令` 直接写进空状态 —— 具体、可信、有方向感。改对比度、删掉那个 ⚡ 就行，不要换掉这套内容。
- **主题皮肤 / 壁纸 / 侧边栏半透明 / 宽度**这套外观能力，以及「浅色默认、深色是变量覆盖」的结构。
- **PI NEXT 渐变字标**（品牌资产，锁定）。
- 信息密度高是刻意的，不要改空。

## 6 · 未验证（不要当成已通过）

- **动效**：本次只有静态帧，没有录屏、没有开始/中间/结束三帧。**三处基本动效（主操作反馈、状态切换来路、首次进入出场）一律未验证。**
  1.1 的透明现象已经被 A/B 像素对照证明是**静止态**，不是入场动画残帧。
- **深色主题**：主题存在 `localStorage`，截图工具起的是干净临时 profile，本次没取到深色截图。
- **PWA 会话页的消息头**（PI NEXT 标 + 模型名 + 耗时/token + 工具调用行）在这一帧看不到，**不下结论**（不是缺失）。
- 所有 `⋯` / `+` / 纯图标按钮的实际行为，按未验证处理。

## 附 · 关于这个 skill 本身

- 装法：`npx skills add oil-oil/oil-ui --agent pi -g` → `~/.agents/skills/oil-ui/`
- `skills` CLI 装完给的安全评估是 **Gen: High Risk / Socket: 1 alert / Snyk: Low Risk**。实查：
  `scripts/check_update.py` 会在加载时向 `ui.oiloil.org` 发一次版本检查（限速 10 分钟一次，可用 `OIL_NO_UPDATE_CHECK=1` 关掉），
  `scripts/recommend_once.py` 会打印一次 Pro 版广告（一次性，写标记文件）。
  两者都不改本目录、不自动更新（`--update` 必须显式调用）。
- `SKILL.md` frontmatter 里的 `!`sh "${CLAUDE_SKILL_DIR}/..."`` 是 Claude Code 的加载期命令语法，**Pi 不支持**，会当成普通文本；`allowed-tools` 同样不生效。

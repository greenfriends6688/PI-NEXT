# 逐帧结构核对手册（2026-10-05）

> 目标：**画板 DOM 上有的，产品 DOM 必须一模一样有**；不一样的改到一致；
> 板上有而产品完全没有的（真·新增内容）补出来。
> 工具：`scripts/struct-diff.mjs` + `scripts/struct-specs/*.mjs`。
> 契约：`design/v5/LANDING.md`（铁律一：抄画板 DOM 原文，禁止只加类、禁止截图模仿）。

---

## 0 · 为什么以前栽在这里

V5 换皮跑完 86% 的类，但用户打开一看「和画板完全不一致」。复盘：验收时只验了
**「类名在不在库里」**（`land-status` / `check-v5` 全绿），从没验过**「板面那一段在产品里
长这样」**。这就是 v1 翻车的同一个坑的第七次复发：**类名对上了，结构没对上**。
本手册就是那道缺失的仲裁。

## 1 · 工具

```bash
node scripts/struct-diff.mjs scripts/struct-specs/<你的spec>.mjs
```

输出：`板 N 节点 / 产品 M 节点 · 偏差 K`，逐条列：

| 标记 | 含义 | 怎么修 |
|---|---|---|
| `MISSING` | 板上有、产品这一段没有 | 照板补 DOM（这多半是「新增内容」） |
| `EXTRA` | 产品多出来 | 多半是根节点选错造成的错位噪音；确认后再删 |
| `CLASS` | 同一节点 `缺 [...] 多 [...]` | 缺 = 补类；多 = 换回板上的类 |
| `TAG` | `板 button ≠ 产品 div` | 换标签（静态件→可点件时 div→button，保留类名） |
| `ICON` | `板 panel-left ≠ 产品 —` | 图标名/有无不一致，按板抄 `<i data-ico>` |

文本与数据不比（板上是样例、产品是真数据）。

## 2 · 一张板的核对流程

```
① 打开板 → 找到这一帧（.d-frame / .m-scene）
② 读懂这一帧要表达什么组件（哪个产品文件负责）
③ 给这一帧写一份 spec：boardRoot（板侧那段）· appRoot（产品侧那段）· app.script（怎么走到这个面）
④ 跑 struct-diff → 按偏差改产品 DOM
⑤ 重跑直到该帧偏差收敛（或只剩已登记的 knownDiffs）
⑥ tsc + eslint + 相关测试
```

### spec 长什么样

```js
export default {
  name: "D-02 侧栏 · 帧 A 展开态",
  board: "v5/web/boards/D-02-sidebar-topbar.html",
  boardRoot: ".d-shell",        // 板侧要比的那段（去掉 d-frame/d-scene 这些家具）
  app: { script: `/* 点开项目组、点第一条会话 */` },
  appRoot: ".app-shell-layout",
  ignore: ["d-grow", "m-grow"],  // 纯占位、无视觉
  maxRows: 40,
};
```

**根节点要对齐**：板侧和产品侧各挑一棵「讲同一件事」的子树（都是侧栏，就都挑侧栏根；
一边是整页壳就只挑壳）。根不同 = 全篇错位噪音。

## 3 · 硬纪律

- **只抄 DOM，不仿画**。偏差里凡是 `TAG`/`CLASS`，一律按板的原文改，不自己发挥。
- **MISSING 就是新增内容**：板上有、产品没有 → 补出来（这正是用户要的「新增的也弄出来」）。
  但若它需要**产品没有的数据源/后端**（板子自己标了「提案」），不要凭空造 —— 写进汇报，
  附上「缺什么数据源、要动哪些 API」。
- **不许改 `design/v5/**`**：那是画板（真值）。只有我（编排者）能改画板。
- **不许删测试、不许 @ts-ignore**：断言因结构变化失败时，改断言成新的等价约束。
- **不许自造类**：只能用 `design/v5/{web,pwa}/system.css` 里已有的。缺件写汇报由我补库+补板。
- **行为零变化**：换皮只改 DOM/CSS，props/state/handler/i18n/快捷键/aria/data-* 全部原样。

## 4 · 报告

每张板交一份：帧号 → 偏差数（改前/改后）→ 补了什么新增内容 → 仍缺什么（含需产品决策的）。

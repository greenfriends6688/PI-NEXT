# Pi Web 设计规范

> 本文是本设计系统里**唯一**的风格与结构来源，写给人看、也写给 AI 画板用。
> 画板清单与计数以 `README.md` 为准；实现与画板不一致的地方记在 `DIVERGENCE.md`。
> 数值全部来自 `assets/tokens.css`；画板里出现的任何数值都必须能在那里找到，否则算错。

---

## 0. 这套规范从哪来

本项目的界面此前**没有统一规范**：颜色散落在 `app/globals.css` 的几套皮肤块与组件内联样式里，
圆角有 4 / 6 / 10 / 12 / 24 五档，字号有 10 / 11 / 12 / 14 / 15 / 16 / 18 / 24 八档，
图标混用 emoji 与手绘 SVG，控件高度有 22 / 26 / 28 / 32 / 36 五档。

本规范参照 `pi参考项目/AcpAgentClient-main/design/`（下称**参考项目**）的路线重建一套统一系统。
参考项目的做法是：**先出一张 Token 表，所有页面画板从它取值；一画板一个可独立实现的界面单元；
画板是功能边界。** 这三条原样搬过来。

**参考项目与本项目的关系**：参考项目是一个 Windows 首发、Flutter 手写的 ACP 桌面客户端；
本项目是一个纯 Web、Next.js 的 Pi Agent 客户端。两者的**信息结构高度重合**（三栏壳、转录卡片、
Agent 面板、文件面板、设置），所以参考项目的画板清单可以**逐条对位**成我们的画板清单
（对应表见 `README.md`）。差异在于：本项目多了「聊天工作区 / 项目双 pane」「皮肤工作室 / 壁纸」
「定时任务」「记忆」「自定义命令」「导入」「用量统计」，少了「ACP Registry 插件市场」
（我们用 npm 包插件 + MCP 服务器）。

## 1. 风格系统（硬约束）

一句话：**Notion 的克制与纸感，Zed 的单一色系与密度，小圆角，无边框按钮。**

### 1.1 颜色：尽量少，同一色系

- **中性色阶只有一条**，10 级，从页面底色到正文前景。整条色阶带**同一个轻微色相偏移**
  （向强调色的色相偏，饱和度极低，最白与最黑都不超过 0.02）。
  层次**全部靠明度差**表达，不靠换色相。
- **强调色只有一个**：低饱和蓝紫 `#5566d8`。只用于四处：
  主按钮填充、焦点环、链接与选中态的文字/图标、进行中的 spinner。**不做大面积底色**。
- **强调色底有面积上限（可验收）**：单块强调色实底**不超过一枚主按钮**（≤ 96×32），
  且**任何一维 ≥ 240 的连续强调色块一律禁止**——一维到了 240，它读起来是「一块底色」而不是「一个控件」。
  强调淡底（`--accent-soft`）只能铺在**单个组件自己**的盒子里，不许跨过两个组件的边界。
  判据：把画板截图缩到 25%，强调色还剩下「几个点」而不是「一片」——过了就是大面积底色。
- **语义色四个**：error `#bc4e39` / warning `#8a6f12` / success `#477f40` / info `#5566d8`，
  各配一个 `.soft` 淡底。只用于**状态图标、状态文字、细状态条**。
  **细状态条高度 ≤ 2px**（可验收）：本系统只有两种——1px 发丝线（分隔、运行中底边）
  与 2px 从属竖线（引用、回答行、子代理）。出现 3px 及以上必须改用「1px 边框 + 徽章」表达，
  理由是 3px 起它就开始抢注意力，而状态条只配提示、不配抢。
- 全套出现的色相**不超过 5 个**（强调 + 4 语义），其余全是中性色阶。
- **禁止**：渐变背景、玻璃模糊、彩色大色块、噪点纹理、emoji。

| 层 | token | 浅色 | 用途 |
|---|---|---|---|
| 中性 1 | `--n-canvas` | `#fbfbfc` | 页面底色 |
| 中性 2 | `--n-panel` | `#f4f4f6` | 侧栏 / 右栏 / 输入框 |
| 中性 3 | `--n-surface` | `#eeeef1` | 芯片 / 次级块 / kbd |
| 中性 4 | `--n-hover` | `#e7e7eb` | 悬浮实色 |
| 中性 5 | `--n-border-subtle` | `#e2e2e7` | 发丝分隔线 |
| 中性 6 | `--n-border` | `#d3d3da` | 控件轮廓 |
| 中性 7 | `--n-placeholder` | `#8b8b96` | 占位符 / 弱化图标 |
| 中性 8 | `--n-muted` | `#62626e` | 次要文字 |
| 中性 9 | `--n-text` | `#33333d` | 正文 |
| 中性 10 | `--n-strong` | `#1e1e26` | 标题 / 强调前景 |

深色对位（`--` 前缀同名，`_dark` 只在 `.dark` 里覆盖）：`#17171c / #1d1d23 / #24242b / #2c2c34 /
#303039 / #43434e / #7e7e8a / #9b9ba6 / #d5d5dc / #f0f0f4`。
**一个浅色 token 名对应且只对应一个深色值，没有深色专有 token。**

### 1.2 表面与边界

- **三级表面**：页面底色 → 面板（侧栏 / 右栏 / 输入框）→ 弹层。用明度区分，
  弹层再加阴影，**全系统只有两种**（可验收）：
  | 场景 | token |
  |---|---|
  | 浮层：菜单、下拉、悬浮提示、通知条 | `--shadow-popover` |
  | 模态与遮罩层：对话框、抽屉、灯箱、底部面板 | `--shadow-modal` |

  不允许第三种，也不允许给「重要程度」分级加阴影——分级靠层级与边框，不靠影子深浅。
- **分隔用 1px 发丝线**（`--n-border-subtle`），**不用阴影分层**。
- **卡片**（工具卡、权限卡、计划卡、diff 卡…）：1px 发丝边框、无阴影、**无左侧彩色竖条**、无渐变。
  唯二例外：权限卡用强调色边框 + 淡底（它是唯一需要抢注意力的卡）；
  子代理卡用 2px 左侧强调线（它是唯一有父子层级的卡）。

### 1.3 圆角：小

- 三档：**3 / 4 / 6**，上限 6。
  - 3：芯片、kbd、小徽章
  - 4：按钮、输入框、菜单项、行容器、开关（开关用 pill）
  - 6：卡片、弹层、面板、输入框外壳
- **不出现 8 以上的圆角**；不出现胶囊按钮（只有开关轨道与全圆徽章用 `--radius-pill`）。

### 1.4 按钮：无边框，悬浮出深色容器

- 默认态所有按钮**无边框、无填充**，只有图标或文字。
- 悬浮态出现一个**比所在表面更深的中性容器**：`--overlay-hover`（约 6% 深色叠色）；
  按下再深一档 `--overlay-active`（约 10%）。容器圆角 4，**比内容水平各多 6px、垂直各多 4px**（定死，不再是「4–6」）。
  理由：水平方向内容常常连成一条，4 的余量会贴上去；垂直方向上下紧邻别的文字，6 的余量会读成两行。
- 选中态（当前标签、当前会话、当前设置分节）用与按下态相同的容器，**再加强调色文字或图标**。
- **唯一例外是主按钮**（发送、保存、安装、允许）：强调色填充 + 白字，同样圆角 4，高度与普通按钮一致。
- 危险动作（拒绝、移除、删除）用 ghost 样式 + error 色文字，**不用红色填充**。
- 焦点环：1.5px 强调色描边，偏移 1px，**只在键盘焦点时出现**。

### 1.5 字体与字阶

- UI 字体 **Geist**（Google Fonts），回退 `system-ui`；中文回退 Noto Sans SC。
  等宽 **Geist Mono**，回退 `ui-monospace`。
- 字阶**只留五档**：11（元信息）/ 12（次要）/ 13（正文与控件，基准）/ 15（标题）/ 20（空态大字）。
  正文行高 1.5，控件行高 1.35。等宽 12.5。
- **数字**（token 数、耗时、费用、行号、计数）一律开等宽数字 `font-variant-numeric: tabular-nums`。
- 字重**只用 400 与 500**，标题 500，不用 600 及以上。

### 1.6 间距、控件尺寸、图标、动效

- **4px 网格**；常用 4 / 8 / 12 / 16 / 24 / 32。
  唯一例外是徽章内边距 `--space-chip`（`1px 5px`）与 kbd 的 `--space-kbd`（`0 4px`）。
- **控件高度三档**：24 紧凑（芯片、行内按钮）、28 标准（工具栏、输入框内控件）、32 主输入区。
- **图标**：单线、1.5px 描边、**16px 网格**（工具栏可用 14），同一套风格，**内联 SVG**。
  图标一律取自 **lucide**（<https://lucide.dev>），**禁止 emoji、禁止图片素材**。
  当前用到的图标集在 `assets/icons.js`，用法：`<i data-ico="search"></i>`。
- **图标与文字必须垂直居中**（硬约束）。`icon + 文字` 或 `文字 + icon` 的组合里，
  **文字不许比图标低**。实现靠清掉行高 strut，三条规则写在 `assets/board.css` 的
  「图标与文字的垂直对齐」一节：`<i data-ico>` 自身 `inline-flex + line-height:0`、
  内层 `<svg>` `display:block`、`.pw-ico` 包装层同样 `line-height:0`。
  **不要**在个别位置用 `margin` / `translateY` 硬凑；改完跑 `scripts/check-align.mjs`，必须报 0 处偏差。
  折行的提示条是例外：图标按 `flex-start` 对齐，再把图标盒高度撑成首行盒高
  （`height: calc(var(--lh-body) * 1em)`）自动居中。
- **动效有十二项，全部登记在 `assets/tokens.css` 第 12 节，全部在 `05-motion.html` 上真在播**：

  | token | 值 | 用途 |
  |---|---|---|
  | `--ease` | `cubic-bezier(.215,.61,.355,1)` | 全系统唯一曲线 |
  | `--motion-fast` | 120ms | hover / 颜色 / 等待期减弱 |
  | `--motion-base` | 160ms | 展开折叠 / 弹层出现 / 列表行入场 |
  | `--motion-transition` | 200ms | 整块替换（切会话 / 切标签） |
  | `--motion-layout` | 240ms | **只用于布局尺寸**（侧栏折叠 / 面板宽度）——唯一允许 >200ms 的一类 |
  | `--motion-sweep` | 1400ms | 侧栏扫掠亮点线周期（`linear` · infinite） |
  | `--motion-rise` | 8px | 整块替换上移 |
  | `--motion-stream` | 4px | 流式内容入场上移 |
  | `--motion-pop` | 4px | 弹层位移 |
  | `--motion-sheet` | 14px | 移动端抽屉上滑 |
  | `--motion-stagger` | 40ms | 成组错开（**最多 3 项**，第 4 项起不延后） |
  | `--motion-hint` | 1600ms | 提示类：呼吸（持续来回）+ 跳转高亮（一次性），同值同曲线 |
  | `--opacity-pending` | 0.5 | 等待期减弱 |

- **五类转场**：整块替换（200ms）/ 带等待期的替换（120ms + ? + 200ms）/ 弹层出现（160ms）/ 展开折叠（160ms）/ 静默布局（240ms）。
  **不在这五类里的转场不做。**
- **轻量交互五条**：悬浮进出同一条 120ms；**按下 0ms 立即换色、不做过渡**；**焦点环 0ms 立即出现/消失**；
  展开折叠 160ms（高度 + 透明度同起同止）；开关 120ms。
- **两处 `linear`，仅此两处**：侧栏「运行中」的扫掠亮点线（1400ms infinite，表达「匀速、还在跑」，
  用 ease 会读成「刚动了一下就停了」）与 spinner 的匀速圆周。
- **不弹跳、不缩放文字、不同时动 3 个以上属性、内容类动效不超过 200ms。**
  `prefers-reduced-motion: reduce` 下**一律停在终态**（不是加快、不是变短）。
- **kbd 快捷键芯片**是设计元素：等宽 11、发丝边框、圆角 3。

## 2. 结构与交互来源

### 2.1 信息结构照产品现状

本项目的界面结构**已经定死**（三栏壳、侧栏双 pane、转录卡片、右栏标签、设置分节）。
本规范**只重做视觉，不改结构**：布局层级、控件有哪些、点了发生什么，一律照现有实现。
画板里的文案（含中英混排）照产品现用的 i18n 文案取，示例数据（会话标题、agent 名、文件名、
命令输出、计划条目）可直接复用真实内容。

**优先级规则（画板是功能边界 ↔ 结构照实现，冲突时看哪边）**：

| 冲突类型 | 听谁的 | 动作 |
|---|---|---|
| 「这个功能有没有被设计过」（§ 4 清单里有 / 没有） | **画板是功能边界**（README） | § 4 未列的功能不画进画板；实现里出现了 → 写进 `DIVERGENCE.md` 等裁定 |
| 「同一个功能在实现里长什么样」（尺寸、层数、状态集合、文案） | **结构照实现** | 画板照实现改，实现有而画板没有的中间态**不许自创进画板** → 写进 `DIVERGENCE.md` |
| 用户已经裁定过的结论（如 § 2.7 的「输入框下方无常驻横条」） | **裁定高于前两者** | 先改画板，再改实现；两者同一次提交改完，不留中间态 |

一句话：**画板决定「有没有」，实现决定「什么样」，裁定决定「听谁的」。**

### 2.2 三栏壳

```
┌────────────┬──────────────────────────────┬──────────────┐
│ 侧栏 280   │ 主区（聊天 或 右栏内容）      │ 右栏 420     │
│ 品牌行     │ 顶栏 36                      │ 标签条       │
│ 导航       │ 转录（居中 800）             │ 文件树/查看器│
│ 项目/聊天  │ …                            │ 终端/浏览器  │
│ 会话树     │ 输入框（居中 800）           │ Git 图       │
│ 底部设置   │ 统计条                       │              │
└────────────┴──────────────────────────────┴──────────────┘
```

- 侧栏可折叠成 52px 导轨；宽度可拖 220–480。
- **工作区角色可对调**：聊天与右栏内容互换左右。
- 窄屏（≤1024）侧栏变抽屉浮层。

### 2.3 转录区：过程时间轴是唯一的过程形态

参考项目把工具调用画成**一张张独立的卡**；本项目现有实现把一轮内的工具调用收成
**一条带竖线的过程时间轴**（`ProcessGroup`）。本规范**保留本项目的这一形态**，
因为它更省纵向空间、失败行能在竖线上直接标红：

- 汇总行：`N 个文件 · M 条命令 · K 次工具调用 · J 次失败 · L 段思考`，右侧一个状态徽章。
- 步骤行：左侧小图标（推理 / 读取 / 搜索 / 编辑 / 运行 / 计划 / 产物），
  中间动词 + 参数（等宽），右侧耗时。
- 失败行动词与图标转 error 色，不另开一张卡。
- 需要看完整输出时，展开成一张**工具卡**（等宽输出区 + 「原始入参 / 复制」页脚）。

### 2.4 转录卡片全集（本项目）

| 组 | 卡片 |
|---|---|
| 文本 | 用户消息、助手正文（Markdown）、代码块、GFM 表格、数学公式、Mermaid 图 |
| 过程 | 思考折叠块、过程时间轴、工具卡（完成 / 失败 / 取消 / 展开）、diff 卡、终端卡、子代理卡 |
| 交互 | 权限卡、计划卡、压缩卡、非文本内容块（图片 / 文件 / 音频）、回合结束行、错误与状态条 |
| 空态 | 新会话首屏 + 四张起始提示卡 |

### 2.5 输入框

一行放：附件 `+`、模型、思考档、权限档、工具档、压缩、上下文环、声音、发送/停止。
上方是附件与引用芯片条；下方是会话统计条（等宽数字 + 上下文占用环，>70% 警告 / >90% 危险）。
`@` 唤起引用菜单（文件 / 会话 / MCP / Todos），`/` 唤起命令菜单。

### 2.6 侧栏会话活动指示（状态标记一律在右侧）

会话行**左侧不放任何状态标记**。三种活动态互斥，都画在 `N 条消息` 之后或行的底边：

| 会话态 | 底边 | 右侧标记 | 行高 |
|---|---|---|---|
| 空闲 · 已读 | 无 | 无 | 48 |
| 运行中 | 1px 常亮线 + 96px 强调亮点匀速掠过 | 无 | 58 |
| 完成 · 未读 | 无 | 6px success 圆点 | 48 |
| 等你处理 | 常亮线（撤掉扫掠） | warning 文字标记（待授权 / 待输入） | 58 |
| 已取消 / 已失败 | 无 | 无 | 48 |

取消与失败**不在侧栏表达**——那是转录里结束行的事。侧栏只回答三个问题：在跑 / 有结果没看 / 等你。

### 2.7 转录右缘：迷你地图与上下文

- **迷你地图是两件东西**：右缘一条 **36px 导轨**（6px 圆点节点，间隔上限 50px，当前节点 8px 转 accent，
  标题节点用 muted 区分）+ 悬浮时在导轨**左侧**展开的 **320px 时间线浮层**。
  **浮层高度 = 内容高度，上限 = 转录区高度**——不是通高（通高在 8 轮以内的短会话里会在下方留六成空白，像面板坏了）。
- 时间线浮层每一轮是「编号列 34px + 内容列」：编号等宽 10px、**对齐内容首行**（不整块居中，否则单行/两行行的编号会上下跳动），
  下面挂工具数徽章（有工具调用才出现）；内容列第一行是用户消息首行，有回复时多一行回答首行——
  **回答行是轮的一部分，带左侧 2px 从属竖线；字母 `A` 只在编号列出现一次**（它是「跳到这条回答」的锚点）。
  当前轮用 6% 底 + 左侧 2px 强调条，编号转 accent。
- **图钉固定态只染图标 + 下边线**，不铺强调底色（整条上色会盖过内容）。行 hover 用全系统的 6% 叠色。
- 浮层顶部一个「图钉」按钮（36px 高）：固定后面板跟着指针自动滚到最近一轮；不固定则移开 250ms 收起。
  浮层里**滚动条隐藏**（320px 窄栏里再切一条灰边显得脏）。
- **用量不进长条**：输入框左下角只有一个上下文圆环（百分比），悬浮才展开浮窗给出
  `Context / Rules / 本轮 ↑↓ / 花费 / 结束原因` 与「压缩上下文」。输入框下面**没有第二条横条**。

## 3. 不得出现的内容

以下是**画板专用之外的禁用项**，任何画板都不得出现：

- **emoji**。所有图标用 lucide 内联 SVG（`data-ico`）。
- **图片素材**。图片预览、壁纸缩略一律用 CSS 占位（斜纹/色块），不放真图。
- **渐变背景、玻璃模糊、彩色大色块、噪点**。
- **8px 以上的圆角**、胶囊形按钮。
- **token 表之外的数值**。画板里每个颜色/字号/间距/圆角/时长都要能在 `assets/tokens.css` 找到。
- **编造的硬数据**。分两类处理（可验收）：
  - **可以直接用真实内容**：会话标题、agent 名、文件名与路径、命令输出、计划与待办条目、
    i18n 文案。这些照抄产品里已有的，不编。
  - **只能用样例，且必须量级合理**：价格、日期、token 数、耗时、条目数。样例的量级固定为
    上下文上限 `1M`；单轮 `↑ 5k–20k / ↓ 1k–5k`；本轮花费 `$0.01–$0.10`；单轮耗时 `2–10s`；
    token 计费 `260k / 1M` 这类写法。**出了这些量级就是编造**，
    也不许出现产品从未对外宣称的数字（用户数、留存、性能指标、价格表）。

## 3.5 PWA（`70`–`89`）

**一套真值，两套画板。** 编号即分组：`00–69` Web（桌面）/ `70–89` PWA（手机与平板）/ `90–99` 跨端。
PWA 画板与 Web 画板**共用同一份** `assets/{tokens.css, board.css, icons.js}` ——
差别**只在版式组合**（桌面三栏 vs 手机单栏 + 覆盖层），**不在颜色 / 字号 / 圆角 / 控件 / 动效**。

> 不建第二套 token 或第二套 `pw-*` 基元。上次「设计落不了地」的根因就是同一个视觉有两个来源；
> 做成两套等于把那个错误放大一倍。完整理由见 `docs/design-v2-plan-2026-10-04.md` §0。

### 帧尺寸

| 档 | frame | 对应实现断点（`hooks/useIsMobile.ts`） |
|---|---|---|
| 手机 | **390 × 844** | `useIsMobile` ≤ 640 |
| 窄手机 | **320 × 690** | `useIsNarrowMobile` ≤ 480 |
| 平板 | **1024 × 768** | `useIsCompact` ≤ 1024 |

断点数值**只取上面三条 media query**，不允许在画板里另取整。

### PWA 硬约定（2026-10-04 复核**维持原裁定**，见 §3.6）

- **与桌面完全同构**：不新增底部控件条、不新增底部弹层。控件都在输入框那一行里；
  窄屏放不下的顶栏动作收进一条**覆盖顶栏**的工具条（就是桌面顶栏右侧那一排，一个不少）。
- **变的只有宽度与触控尺寸**：抽屉 272 宽、触控目标 36、滚动条 6px、安全区。导航范式与控件一律不变。
- **触控目标 36 × 36**（桌面 28）；**滚动条 6px**（桌面 8px）；动作**不依赖 `:hover`**（触屏没有悬浮）。
- **安全区**：顶部状态栏 24 高、底部 home indicator 22 高；standalone 下视图高度走 `--app-viewport-height`。
- **可点**：PWA 画板是流程页，必须接 `assets/board-demo.js` 的 `data-demo-*` 属性，
  并由 `scripts/check-demo.mjs` 验证。Web 组的**规格册**（把多个状态并排展示的那种）不必可点。
- **设备外框**（`pw-phone` / `pw-phone-inner` / `pw-statusbar` / `pw-homebar` / `pw-notch`）是**画板家具**，
  只在 PWA 画板里出现，不进产品；产品的移动端就是同一个壳收到窄屏。

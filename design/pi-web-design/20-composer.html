这一张在定什么

  • 一行控件的固定顺序：左端 +（附件 / 上下文），然后是四个下拉（模型 → 思考档 → 权限档 → 工具档），再可选压缩；右端是上下文环 → 声音 → 发送。左端与右端之间用 grow 撑开。
  • 控件高度只用 24：输入框里的下拉与图标按钮都是 24（紧凑档），因为它们是「行内控件」不是「工具栏控件」。
  • 发送键是唯一的强调色实心块，圆角 4、28 见方。三种状态：空闲（accent 箭头）/ 流式中（error 方块）/ 禁用（中性底 + 弱化箭头）。
  • 附件芯片在正文上方，不挤占输入行；引用上下文条用左侧 2px 强调线 + 等宽来源标注。
  • 统计条在输入框下方，是一条独立的发丝边框块，全部等宽数字；上下文环三档配色（accent / warning / error）是唯一会变色的控件。
  • 排队条在输入框内部上方：每条给序号徽章 + 文本 + 三个动作（编辑 / 立即发 / 移除）。
  • 输入框里的 token 有着色：@ 引用与 / 命令用强调色 + 点状下划线；正在输入、还没成形的半个 token 不着色。实现上是「透明 textarea + 高亮层」，两层必须共用字号。
  • 输入框可拖高：顶部一条 12px 的把手（默认弱化 / 悬浮加深 / 拖拽中转强调色），双击复位，上限 40vh。长提示词不必在小框里滚。
  • 阅读态会自动塌陷：向上翻阅（离底 > 120px）时收成一行文本、隐藏工具栏，把视口让给消息；回到底部或聚焦输入框立刻展开。只认真实用户滚动意图，且必须做方向跟踪（否则会被浏览器的「夹回底部」骗到来回翻转）。
  • 上下文浮窗挂在左下圆环上：Context 10k / 1M + Rules，有费用信息时多两行（本会话花费、本轮 in/out）；协议没给 cost 时整段省略，不留空行。
  • 输入历史：空输入框里按 ↑ / ↓ 翻自己发过的消息，右端显示「历史 3 / 12」；手动改字即退出浏览，连续重复的不入栈。
  • 模型错误挂在输入框上方一条，不挡输入：写明哪个模型、为什么不可用，给「换一个模型」与关闭；发送键转禁用。
  • 流式有两种模式：Steer（立即打断，accent）与 Follow-up（排队，中性）。选中后在输入框下方常驻一句后果说明——「会打断」和「会排队」是完全不同的预期，不能只靠图标区分。
  • 「收起控件」与自动塌陷是同一个状态：手动按钮在工具栏右端，自动触发是向上翻阅；两者折叠形态与展开条件一致，不各做一套。

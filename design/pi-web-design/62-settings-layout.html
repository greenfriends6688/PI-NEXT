新框架的硬规则 · 每一条都对应一个实测到的现状问题

尺寸

  • 设置内容区 = 1440 − 200 导航 = 1240；左右内边距各 40 → 可用 1160。
  • 全站只有两个内容宽度：列表 300、内容 760（两栏块流则各 570）。
  • 列表与内容之间 gap 16；760 之后剩下的 80 留白，不做拉伸。
  • 页头 padding 24 / 40 / 12；工具栏高 40；内容区 padding 16 / 40 / 24。

滚动

  • 分节内容区是 flex column + min-height:0；页头与工具栏不滚。
  • 列表页：列表列与详情列各自滚，互不影响。选中第 20 项时详情仍在视野内。
  • 块流页：只有块流区滚，一个滚动条。
  • 详情内部不再套第二层滚动（技能页的 SKILL.md 现在是内部滚动框，会把长正文裁掉）。

页头

  • 12 个分节全部有页头。现在技能 / 子代理 / 插件 / MCP / 用量 / 自定义命令 / 导入 7 页没有。
  • h2 必须是内容区的直接子元素——归档 / 导入 / 用量 / 自定义命令把 h2 包在 .settings-general 里，board.css 的 > h2 选择器没命中。
  • sub 写「这页是干嘛的」，不写数据；计数进工具栏的等宽徽章（定时任务现在把「任务列表」当 sub）。
  • 页级动作最多 2 个，1 主 1 次，永远在页头右端。

禁止项

  • 不许有浮在视口右下角的按钮（模型页的「保存」现在就是）。
  • 页脚不放动作，也不放别的页面的统计（MCP 页现在显示插件页的 4 ext · 7 skills）。
  • 同一个动作不在两处出现（插件页页头与页脚各有一个「检查更新」）。
  • 空态说明不许脱离空态本体（自定义命令页那句「保存后斜杠面板立即可用」飘在右列中段）。

这一张在定什么

  • 12 个分节收敛成 2 种骨架：有「条目」概念的用「列表 300 + 内容 760」，没有的用「两栏块流 570 × 2」。现在实际存在 4 种（单列块流 / 列表+详情 / 顶部整宽条+两栏 / 块流+底部两栏）。
  • 唯一滚动在内容区，页头与工具栏固定；列表页的两列各自滚。这解决「选中列表第 20 项后详情滚出视野」。
  • 全站两个宽度：列表 300、内容 760。字段行的「标签—控件」跨度从 1000 收到 760（块流页 570）。
  • 动作四级归位：页级 → 页头右端；列表级 → 工具栏右端；条目级 → 详情头右端；表单级 → 表单块底部。页脚不再放动作。
  • 页头恒在，且 h2 必须是内容区直接子元素 —— 现在有 7 页没有页头、4 页把 h2 包错层。
  • 空态三态各有落点：列表空在列表列内（32px 图标）、详情未选在详情列居中（40px 方框）、整页空在内容区居中（20px 标题 + 出口动作）。
  • 「内容区不滚」只给纯列表页（.pw-scontent.is-fixed）：分节里只要还有别的块（状态块 / 工具块 / 说明块），就必须用默认滚动 —— 否则超出的部分会被静默裁掉，连滚动条都没有。记忆页实测被裁 243px。
  • 固定轨道的长跨度图表不要放进 570 的一栏：年度热力图是 53 周 × 14px ≈ 742px 的定宽网格，塞进半栏只剩 514px 可见，而最近的活动全在最右端 —— 看起来就是一整片空白格子「像假数据」。它要占一整行。
  • 这一张是提案，落地前需要裁定：是否接受「列表 300 / 内容 760」这两个固定宽度、是否接受把子代理页顶部的两条整宽设置行收进列表列。裁定结果记入 DIVERGENCE.md。

右栏宽度逻辑的抽取方案

现在右栏宽度被三处硬编码：AppShell 的初始值、resize 的 clamp、以及窄屏的兜底。建议合成一个 useResizablePanel 的返回值，让三处都读同一个 width。

要做的三件事

  1. 把 clamp 的上下界抽成常量，交给 hook 持有
  2. 窄屏（≤1024）时不再 clamp，直接走抽屉
  3. 双击分栏把手复位到默认宽度

检查清单

  • 抽出 useResizablePanel
  • 三处调用点改读返回值
  • 补窄屏与宽屏两条单测

上下文占用率按 ρ = u / C 计算，其中 u 是当前会话已用 token、C 是模型上下文窗口。压缩的触发阈值取：

ρtrigger = 1 − ( rreserve / C ) ，rreserve = 16 384

也就是给最后一轮留出 rreserve 的余量；C = 1M 时阈值约 98.4%。

这一张在定什么

  • 用户消息靠右、助手靠左：用户消息是气泡（发丝边框 + 面板底色，圆角 6），助手是通栏正文（无边框无底色）。这个不对称是刻意的，让人一眼分清谁说的。
  • 气泡有四个态：默认 / 点击聚焦（描边转强调色 + 3px 淡底光晕）/ 悬浮出操作 / 编辑中。悬浮动作是「复制 / 编辑 / 从此处回退 / 新会话分叉」四项。
  • 编辑是「重起一轮」不是「改字」：保存并重新生成会截掉这条之后的全部轮次。所以按钮文字写明后果，并在下方挂一条 warning 说明会截掉几轮——不让人以为只是改个错别字。
  • @ 文件芯片用强调色文字 + 中性底，不用蓝色填充；引用上下文用左侧 2px 竖线缩进，与正文区分。
  • 代码块只有一种头：语言标签 + Copy。没有行号列也可以（短片段省略行号），长片段才带行号。
  • 任务清单的勾选框用强调色，完成项文字转弱化灰 + 删除线；不用绿色对勾（绿是 success 语义，留给状态）。
  • 表格偶数行用面板底色做斑马纹，边框只有发丝线一级，数字列右对齐并开等宽数字。
  • Mermaid 失败态不吞掉内容：退化成源码 + 一行 warning 说明，并给重试。

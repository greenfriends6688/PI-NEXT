本段是设计提案：本项目目前没有 ACP agent 认证流程（只支持模型供应商的登录，见画板 41）。画在这里是为了「万一接的 agent 需要认证」时有据可依。

这一张在定什么

  • 更新检查是四态 + 一个布尔：update-available / up-to-date / unsupported / error，外加 checking。「不支持检查」（git 型、本地检出）与「检查失败」是两回事，不能合并成一句「无法检查」。
  • 有更新时主按钮转 primary（「更新」），版本号从弱化转 accent 并写成 v0.9.2 → v0.9.3；没有更新时右侧只剩一个 ghost 的「检查更新」。
  • 检查中按钮文案换成「检查中…」并禁用，不换图标位置、不改布局。
  • 插件列表项四种标记互斥：已启用 / 可更新 / 已禁用 / 已过滤。「已禁用」与「已过滤」整行弱化到 60%。
  • 技能只给一个 ↑ 指示器，不放大徽章——技能可能几十条，每行一个徽章会吵；点进详情才给按钮。
  • 应用自身的更新提示只出现在新会话空态，是一条 accent 的 inline 链接 v0.9.5 ↗；没有更新时整条不渲染，检查失败静默（绝不打断新会话）。
  • 判据只判不等：最新 stable 版本 > 当前版本。本 fork 发 GitHub release 不发 npm，所以不去问 registry。
  • agent 认证不弹模态框：先在转录里出一条状态卡，点「开始认证」才开方式选择；terminal 型在一个可见终端里跑，验证码用等宽大字 + 字距撑开，方便抄。
  • 认证成功后自动重试刚才那次 session/new，不让用户回来再点一次。

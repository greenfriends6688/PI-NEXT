这一张在定什么

  • 权限卡是唯一用强调色边框 + 淡底的卡：它需要用户决策，必须抢注意力。动作收成三档（允许一次 / 本会话始终 / 拒绝），范围下拉另开一个弹层。
  • 已回应的权限收成一条记录：不折叠、不抢注意力、不给按钮，只留「允许了什么 + 时间 + 原始入参」。
  • 计划卡的勾选三态：已完成（弱化灰 + 删除线）、进行中（强调色实心）、未开始（空框）。折叠态显示「当前：X · 还剩 N 项」。
  • 压缩卡是单行块，不做成大卡；三态用图标与边框色区分（accent spinner / success / error）。
  • 内容块按类型给形状：图片给缩略框、资源文件给文件卡、音频给波形条、不可渲染给兜底文件卡 + 下载。
  • 回合结束行按 stopReason 分色：stop 是 success；length 是 warning；error 是 error；aborted / deferred / pending 是中性；toolUse 用强调色（它表示「没结束」）。非正常结束一定要带一句人话解释。
  • 词表以 pi 为准，不是 ACP 的：真实取值就这七个——pending | stop | length | toolUse | error | aborted | deferred（@earendil-works/pi-ai 的 StopReason）。 参考项目那套 end_turn / max_tokens / max_turn_requests / refusal / cancelled 是 Zed 的 ACP 词表，本项目里一次都不会出现，不要照搬。
  • 「等你处理」有两个位置：转录里权限卡下方一条 Awaiting Confirmation 等待行（告诉你在等什么），以及输入框上方一条停靠条（Awaiting Permission / Awaiting Input，各带一个 Scroll 定位）。两处都只在当前会话挂起时出现，都不弹模态框。
  • 协议兜底要显式说出来：客户端不认识的 session/update 变体会被丢弃，丢弃了就给一条 warning 状态条写明「N 条未知会话更新已丢弃」并给「看清单」——静默丢弃会让人以为 agent 卡住了。
  • 通知条三色：error / warning / success，最多 3 条、6 秒自收、鼠标停着不收、可点 × 关、同一句不叠。

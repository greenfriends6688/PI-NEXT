这一张在定什么

  • 移动端与桌面同构：控件一个不少、位置一个不改。窄屏只做两件事——把三栏折成单栏、把放不下的顶栏动作收进一个覆盖式工具条。
  • 没有「底部控件条」：附件的上传、@ 引用、/ 命令本来就在输入框里的 + 与文本输入中，不需要在输入框下面再挂一条。任何「另辟蹊径」的新交互都不做。
  • 「更多控件」展开在顶栏：它是桌面顶栏右侧那一排的同一批动作（历史 / 生成标题 / 子代理 / 分支 / 系统提示词 / 工具定义 / 导出 Markdown），展开成一条覆盖顶栏的条，点 × 收起。
  • 顶栏 48 是移动端唯一的高度差（桌面 36）：触控目标要够大，图标按钮统一 36×36。
  • 抽屉侧栏与桌面侧栏内容完全一致，只是宽 272、圆角归 0、右侧一道阴影，底下垫 32% 遮罩且正文不可交互。
  • standalone 的三处取舍：① 无浏览器地址栏，顶部留状态栏安全区；② 视图高度走 --app-viewport-height（standalone 下 = 100vh），避免地址栏收起时跳动；③ 底部留 30px home indicator 安全区。
  • 安装提示分平台：Android / 桌面 Chrome 走 beforeinstallprompt 给「安装」按钮；iOS 没有这个 API，只给「点分享 → 添加到主屏幕」。
  • 粗指针只改尺寸不改位置：顶栏图标 28→36、顶栏 36→48、滚动条 8→6、悬浮才出的动作改常显。
  • 项目信任在移动端不弹模态框，改成顶栏下方一条常驻横幅——模态框在窄屏会把输入框整个挡掉。
  • 输入框控件行不换行，放不下时右侧裁切（overflow-x: clip）：横向滚动条在输入框里读起来像 bug，裁切读起来像「这行满了」。
  • 断点按实现对齐：三档宽度直接抄 hooks/useIsMobile.ts 的三条 media query —— useIsCompact ≤ 1024（平板档，含手机）、useIsMobile ≤ 640（手机档）、useIsNarrowMobile ≤ 480（窄屏档）。本表与 DESIGN-SPEC.md § 4 的断点表同源，改一处必须改三处。

三种「搜不到」，三种去处
Esc 收起 索引 1,284 文件 · 30 秒前更新
这一张在定什么：
  • 命令中心是弹层，不是新页面。.m-sheet + .m-scrim，底下那一屏会话原样留着 —— 手机上「换页」意味着丢失位置，命令中心恰恰是频繁跳来跳去的地方。
  • 入口留三处，但只有一块界面。顶栏右钮（放大镜，不是「⋯」）· 会话抽屉第一条 · 输入框里的 > 与 @。三处的行结构、排序、选中态完全一致；不一致就会变成三套要分别学的东西。
  • 分段固定、前缀即分类：分段永远是 全部 / 命令 / 会话 / 文件（「全部」在最前）；前缀 > 命令 / # 会话 / @ 文件用一排前缀 chip（.m-tray）做图示，分组标题用 .m-rowlabel；带前缀时只搜那一类，去掉前缀才混排 —— 混排按命中位置排，不按类型排。
  • 结果行统一用 .m-sheet-row，选中态是 .is-on（带对勾 + 强调底色）。同组互斥由 data-demo-list + data-demo-select 驱动，预选中项不排第一 —— 排第一会让「第一条 = 默认项」的肌肉记忆把用户直接送进最不该去的那一项。
  • 最近搜索与快捷入口必须在第一屏。命令中心 90% 的使用是重复动作，靠打字找的成本远高于点两下；历史只留本机 20 条 / 7 天，清历史去设置，不在弹层里再套一层。
  • 底部键位提示用 .m-kbd 写在面板底：↑↓ 选、↵ 开、Esc 收。外接键盘时这行是真的，手机上它至少说明「这块可以被键盘驱动」。
  • 空态要区分「真空态」与「索引未覆盖」。前者给三条可点的去处；后者把这次到底搜了什么逐条列出来（用 / 不用 / 不用 三种标记表达），再给三种「搜不到」各自对应的动作。写成一句「没有找到结果」是这一张最要避免的失败态 —— 用户无法判断是东西不存在、是权限不够、还是还没同步完，三种情况的后续动作完全不同。
  • 三条硬规矩在本张的落法：① 层级一律靠底色 / 圆点 / 徽章 / 图标（.m-dot.run 标运行中、.m-badge.mute 标索引时间），全表零 border-left；② 设置分节一律走 .m-sheet，不新开页面；③ 图标全部 lucide，零 emoji。

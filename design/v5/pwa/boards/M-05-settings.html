手机上的设置是两层：一层 hub（按「你什么时候来改它」分组），一层分节页（进去只讲这一件事）。 两层都不用侧栏导航 —— 手机上横向空间不够摆导航树，改用返回箭头：左上角永远能回去，且不需要菜单键。 控件按手指重做：开关 48×29、滑杆拇指 26px、分段高度 44、输入框高 44， 凡是桌面上「点一下就够」的地方，手机上都要有一个真开关，不能只靠文字描述。

这一张在定什么：
  • 两层，不是三层：hub（.m-settings + .m-cardgroup）→ 分节页。手机上没有空间摆导航树，所以二级页的左上角永远是返回箭头，不藏进 ⋯ 菜单；一次返回直接回到 hub，不做「返回上一级设置」的迷宫。
  • hub 只列 11 个分节：通用 / 模型 / 技能 / 子代理 / 插件 / MCP / 定时任务 / 用量 / 归档 / 导入 / 手机与推送。「外观与输入」「权限与信任」是「通用」里的二级页，从通用进、左上角返回；它们不是第 12、13 个分节。行内副行必须写当前值（「本月 72%」「3 个任务」），不写「查看用量」这种废话。
  • 灰底白卡：.m-settings 是画布灰，.m-cardgroup 是白卡 + 发丝边；卡片之间靠间距分组，不靠标题线。组内最后一行去掉分隔线（.m-setrow:last-child）。
  • 控件按手指重做：.m-switch 48×29、.m-slider 拇指 26px、.m-input/.m-select/.m-picktag 高度取 --nx-ctl-md（44px）。滑杆与输入框在卡内要有 14px 内缩，system.css 只给了 .m-doc-body 可借，缺一个语义化的表单行类。
  • 一行一个控件：带控件的行写成 div.m-setrow 再把控件放进去，避免 button 套 button；纯导航行才写 button.m-setrow。开关全部接 data-demo-switch，主题三档与权限三档接 data-demo-list + data-demo-select（互斥高亮真实迁移）。
  • 信任是一张卡：.m-perm（暖色边框 + 淡底）单独占位，因为它是这套产品里唯一「默认拒绝」的反面 —— 说不清就等于默认允许。撤销信任染红并带「危险」徽章，但不放在 hub 上。
  • 深色不是另一个页面：主题换的是 data-theme 变量板，所有 m- 类一行不改 —— 所以主题档位是 .m-picktag.is-on，不是三套样式。
  • 弹窗宿主不是第二套设置：从会话页可以把「设置 › 通用」以底部面板打开（帧 D），内容与整页宿主同一份，改完合上就回会话原位置；需要重载会话的项在弹窗里只读并说明原因，不退化成只读预览，也不另写一份弹窗专用文案。

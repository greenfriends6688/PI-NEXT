## 0 · 为什么会翻车（三次，形态各不相同，根因同一个）

| 次 | 表面症状 | 根因 |
|---|---|---|
| 1 | `fork-ui.css` 写 `.fork-msg-actions`，组件渲染 `.pw-msg-acts` → 消息动作行**永久透明** | 同一视觉**两个来源**：画板一套类名、产品一套类名，靠桥接层追 |
| 2 | 类名对上了，行还是错的（竖线断截、模型名压瘪） | 只**加类不换 DOM**：`board.css` 假设了自己的结构，类名相同 ≠ 结构相同 |
| 3 | 改一处只对一半 | **同一个值两个令牌文件**，都进运行时、无人校验同值 |

三次的编译器、单测、肉眼评审**全绿**。因为它们缺的不是努力，是**仲裁者**。

V5 的仲裁者只有四个命令，都可复算：

```
node design/v5/scripts/check-v5.mjs      # 静态：令牌/类/图标/接线/静默失效
node design/v5/scripts/land-status.mjs   # 清单：哪些还没进产品（不凭记忆）
node design/v5/scripts/shoot.mjs         # 运行时：真点一遍 + 出图
node scripts/board-diff-all.mjs          # 几何：画板 vs 产品逐选择器对数
```

## 1 · 五条铁律

### 铁律一 · 禁止截图模仿，只抄 DOM 原文

替换一个组件只有一条路：**打开定义它的画板，原样复制那段 DOM**。类名、嵌套层级、
`<i data-ico>`、状态类（`.is-on` / `.is-open` / `.running` / `.on`）一字不动。
产品里只改两处：① 静态文案 → 真实数据；② `div` → `button`/`input`（**保留原类名**，UA 归零在接线层做）。

验收不看「像不像」（截图只做存证），看 **structdiff + 几何对数**。

### 铁律二 · 一个类名只有一个来源

- 类写在 `web/system.css`（`d-`）或 `pwa/system.css`（`m-`）；
- **不许在产品 CSS 里另起同名 `d-` / `m-` 类**；产品侧只允许：UA 归零（button/input 的
  border/background/font）、`cursor`、窄屏语义、滚动容器语义；
- 需要覆盖画板时用 **0-2-0 双类**（`.chat-input-shell.d-composer`）并注释为什么；
- 双向可查：`land-status.mjs` 会列出「画板用了但库里没有」「库里定义了但没画板用」「产品用了但库里没有」。

### 铁律三 · 一个值只有一个来源

- **角色值**（间距/字阶比例/行高/圆角角色/控件高度/动效/层级/透明度）只准在 `base.css`；
- **形态值**（基准字号/色板/圆角值/控件高度/立体）只准在本形态 `tokens.css`；
- 产品运行时**只加载 `base.css` + 一套形态**。同时挂两套 = 老问题换个名字再来一次；
- 改任何前景/背景色后跑 `npm run check:contrast`（需 prod 服务在 30141）。

### 铁律四 · 值必须能被算出来

内联样式只许写**与设计无关**的东西：宽度百分比、动画错峰 delay、几何定位、`z-index` 层的摆放。
颜色 / 字号 / 间距 / 圆角 / 阴影一律 `var()`。**门禁直接拦**，所以这条不会靠自觉。

### 铁律五 · 改完顺手删 stale

DOM 挪了而 CSS 还在，是**已经发生过的事故**（负 margin 把树列顶出面板体）。
同一次提交里 `grep` 旧位置专属规则并删掉。

## 2 · 落地四步法（每个组件都走）

### ① 抄 DOM 原文
打开画板，找到那段片段，原样复制。

### ② 接数据与事件
- 状态映射：产品布尔 → 画板状态类（`.is-on` / `.is-open` / `.on` / `.running`）；
- 事件**不进 CSS**：hover/focus 留 CSS，点击/键盘在 React；
- **浮窗必查裁切**：沿祖先链看 `overflow`。竖向必须 `visible`（或 portal + `fixed`），
  横向可 `clip`。下方放不下才 `.up`；左缘锚定的浮窗别探出卡片左缘。

### ③ 产品侧 CSS 纪律
画板值一个都不重复写；只做铁律二允许的那几件事。

### ④ 验收六件套（全过才算完）

| # | 检查 | 命令 |
|---|---|---|
| 1 | 类型 / lint / 单测 | `npx tsc --noEmit` · `npm run lint` · `npm test` |
| 2 | 设计门禁 | `npm run design:v5` |
| 3 | 几何对数（该组件的 spec） | `node scripts/board-diff.mjs scripts/board-specs/<x>.mjs` |
| 4 | 浮窗裁切审计 | 逐个浮窗沿祖先链查 overflow，0 处裁切 |
| 5 | 交互冒烟 | `node design/v5/scripts/shoot.mjs --only <画板号>` |
| 6 | 改了颜色则跑对比度 | `npm run check:contrast` |

单测被结构变更打断时，**断言新的等价约束**，不许删测试、不许加 `@ts-ignore`。

## 3 · 触发口令（用户说一句话 → 执行什么）

| 用户说 | 执行 |
|---|---|
| **「按 v5 设计落地」/「启动改版 v5」** | `land-status.mjs` 出清单 → 按清单顺序逐项走 §2 四步法 → 每项完成后重跑清单 → 全清后跑 §2④ 六件套 |
| 「只落地 D-04」 | 只做该项，其余不动；同样四步法 + 六件套 |
| 「画板改了，同步产品」 | `check-v5` 找受影响组件 → 逐项 structdiff，列出真实偏差 → 只改有偏差的 |
| 「设计检查」/「画板和产品对得上吗」 | `check-v5` + `shoot` + `board-diff-all`，**只报告不修改** |
| 「新增画板 XX」 | 确认编号未占用 → 只从 `base.css`/本形态 `tokens.css` 取值 → 类先进 `system.css` 且必须有画板在用 → 加进 `README §3` → `check-v5` 绿 |
| 「给 PWA 也来一套」 | 另一形态的令牌与类前缀是另一套，**不许混用**；导航范式与桌面同构，只换手感（圆角/字号/触控尺寸/顶栏） |

**执行者的硬性动作顺序**（缺一步即返工）：

```
1. 读 LANDING.md（本文件）              ← 不许跳
2. 跑 land-status.mjs 拿清单            ← 不凭记忆
3. 逐项：抄 DOM → 接数据 → CSS 纪律 → 六件套
4. 重跑 land-status.mjs，看清单是否真的少了一项
5. 提交：refactor(skin): <画板号> <组件名>
```

## 4 · 陷阱清单（每一条都真翻过车）

| 陷阱 | 事故 | 对策 |
|---|---|---|
| 画板容器 `overflow: hidden` | 向上弹的浮窗 / `@` 菜单被整张裁掉 | 浮层宿主竖向 `overflow-y: visible` |
| 左缘锚定的浮窗 | 宽下拉探出卡片左缘，被 `overflow-x: clip` 裁掉 | 左缘锚定用左对齐浮窗，右缘锚定用右对齐 |
| `min-width: 0` 链 | 逐层 `min-width:0` 让芯片被压成「D…」 | 芯片按内容定宽 `flex: 0 0 auto`；放不下走窄屏折叠形态 |
| 折叠判据用视口断点 | 宽视口开右栏后聊天列很窄，发送钮被顶出裁掉 | 断点 **或** `ResizeObserver` 实测容器宽 |
| 挪 DOM 留 stale CSS | 结构挪了 CSS 还在，负 margin 顶出面板 | 同批 grep 旧规则并删 |
| 内联样式压 CSS | 组件根节点 inline `minWidth:0` 压过任何 CSS 保底 | 改组件内联本身，别用 CSS 赢 inline |
| **同名两义** | `--nx-r-*` 同时是字阶比例与圆角，后者覆盖前者 → 六档字阶全成无效 calc，**一路绿灯** | V5 已拆成 `--nx-f-*`（比例）与 `--nx-r-*`（圆角）；`check-v5` 有专门一条门禁 |
| 同时挂两套形态 | 类名冲突 + 令牌覆盖 | 只挂 `base.css` + 一套形态 |
| 形态类前缀混用 | Web 画板里出现 `m-*` | `check-v5` 直接拦 |
| 源码守卫测试失效 | 换结构后旧断言红 | 断言新的等价约束，不删 |
| dev/prod 共用 `.next` | 混用报 `Module factory is not available` 假故障 | 只走 `npm run dev:clean` / `npm run prod` |

## 5b · 会话筛选口径（两端必须一致，2026-10-04 用户裁定）

**四段，只有这四段**：`全部 · 运行中 · 未读 · 归档`。
桌面侧栏（`D-02`）与手机抽屉（`M-04`）都只允许出现这四个词，且顺序一致。
之前手机端是「置顶 / 全部 / 运行中 / 归档」而桌面端没有显式筛选 —— **两端不一致本身就是 bug**：
用户在手机上学会的分类法，桌面上找不到。`check-v5` 不查文案，但改这两个文件时必须一起改。

## 6 · 裁定（已定，不再重议）

- 本产品**没有登录体系**（`PI_WEB_PASSWORD` 未设时 `/login` 直接 302）。
- 用量与上下文占用**收进上下文环浮窗**，输入框下方不再挂第二条常驻横条。
- 移动端与桌面**导航范式同构**（不新增底部控件条），但 **PWA 是独立形态**：
  基准 17px、圆角 8–28、触控下限 44、渐隐顶栏、光晕立体、灰底白卡。
- 主题只有 light / dark / auto；深色 = 变量覆盖，**组件不许为深色单写规则**。
- 目录选择器系统原生优先，自绘浏览是降级态。
- **设置有两种宿主**：整页（产品现状：`SettingsPage` 的 页头 + 工具栏 + 内容区）
  与弹窗（深链 / 窄屏 / 需要保留当前会话上下文时）。**内容与左导航共用同一份**；
  落地时先做整页（对得上现状），弹窗作为第二宿主。
- 图标一律 lucide + `data-ico`，零 emoji、零手绘 SVG（Git 泳道等已登记例外见 `DIVERGENCE.md`）。
- 色相总数 ≤ 5：中性 + 强调 + 4 语义（success/warning/danger/info）。
- 减弱动效一律**停终态**，不是停回初始。

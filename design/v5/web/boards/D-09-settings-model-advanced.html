请求里不写 reasoning_effort，由供应商按这条消息的难度自己决定。延迟不可预测，但最省。
每轮带 reasoning_effort: none（本模型的兼容开关已开）。快，复杂改动更容易漏。
每轮带 low。适合查资料、改文案这类不太需要绕路的活。
每轮带 medium。多数任务在这一档性价比最好。
每轮带 high。当前默认：跨文件改动、查一个说不清的 bug 都走这一档。

API 覆盖地址
Base URL 覆盖
只对这个模型改接口地址，用于「同一家、另一个端点」。
这个模型已开 1M 上下文 beta。改地址等于换端点，beta 能力不一定在另一个端点上；地址一改，面板会顺手把 beta Header 一并清掉并说明。代理留空时跟随系统设置（http_proxy）。
上限与地址会立刻影响下一次请求，不等重载
这一张在定什么：
  • 高级项的粒度是「单个模型」，不是供应商。同一家供应商下三个模型可以有三套不同上限 —— 因为「能不能用 1M 上下文」是按模型 + 端点分的，不是按供应商分。
  • Header 逐行增删，不给 JSON 文本框。整块 JSON 一旦填进去就没法逐行看、没法逐行删；每行标「来源」（覆盖 Provider / 本行新增 / 未启用）， 空值行整条丢掉而不是发成空串。
  • 冲突提前标，不靠报错发现。输出上限填得比供应商硬上限大时，面板在输入框下面就写清「超出部分被静默截断」，并给一个改对的按钮 —— 否则症状是「模型自己停了」，用户会去查提示词。
  • 兼容开关两层：预设 + 逐项。预设一次性改五个开关；逐项让老网关只关掉出问题的那一个。开关旁边永远有一句「关掉会少什么」， 没有解释的开关会被当成可有可无的装饰。
  • 被钉死的值不假装可改。enabledModels 的 :level 钉死推理档位时，这一栏标「被覆盖」而不是给一个不生效的下拉框。
  • 改地址是换端点，不是换个域名。所以地址一改，面板会提醒 beta 能力（Header）可能不随之而来，并把相关 Header 一并清掉说明原因。

diff-review

对当前分支相对主干的改动做一次自查，输出可勾选的问题清单。默认只读不改 —— 要不要真的落盘由调用它的任务决定。

什么时候用

  • 改动超过 3 个文件，或改动里有删除行

  • 不适用：单文件改文案、加一条日志

它会读什么

git diff --name-only 的输出与每个文件的 diff；不读整个仓库，不读仓库外路径。

这一张在定什么：
  • 三个动作分开：开 / 关 · 安装 / 卸载 · 信任。把它们挤成一个「启用」开关，用户就没法回答「这个技能还在不在」， 也就没法回答「它到底占不占磁盘」。关掉 ≠ 卸载：关只影响加载，文件与版本原样留着。
  • 卸载确认必须逐字写出删什么。商店技能删整个目录、内置技能只能屏蔽、自建目录只删技能子目录 —— 一个笼统的「确认卸载」逼着用户去猜，也逼着他去开 Finder。
  • 来源徽标是三态而不是两态。内置 / 商店 / 手动目录的更新方式、可卸载性、信任要求都不同，来源徽标承担了这件事。
  • 目录优先级是有语义的。同名技能按目录顺序取第一个、不合并不提示，所以顺序可拖但要写清后果；项目级目录固定排在最后。
  • 未信任的目录：列出来但不加载。静默忽略会让用户以为技能不存在；列出来并写清「为什么没加载」才是在帮忙。
  • 说明书与脚本分开说。技能 = 说明书（进系统提示，占 token）+ 脚本（本机执行）。安装确认页把两件事分行， 否则用户对「装个说明书」这件事的风险判断是错的。

网页类工具的策略头
响应头它在声明什么我们因此怎么做
x-frame-options: DENY 这个响应不许被任何页面放进 iframe（点击劫持防护） 内嵌预览直接判「不可嵌入」，改在它自己的浏览器标签里打开
content-security-policy: frame-ancestors 'none' CSP 版本的同一件事，优先级高于 X-Frame-Options 同上；两者同时存在时以 CSP 为准
x-frame-options: SAMEORIGIN 只允许同源页面嵌入 不是我们自己的源 → 同样不可嵌入，提示里说清原因
playwright 拉取 https://app.acme.com/console 的响应头（照抄原始响应，不改写） 不可嵌入
HTTP/1.1 200 OK content-type: text/html; charset=utf-8 x-frame-options: DENY content-security-policy: frame-ancestors 'none' → 右栏「浏览器」面板判定：不可内嵌 → 动作：在系统浏览器新标签打开（保留登录态），模型继续读页面文本
这里不提供绕过开关，也不打算加。这两个头是站点所有者明确表达的「我的页面不许被套进别人的框里」， 那是防点击劫持的策略，不是配置错误。客户端能做的只有两条：说明原因，或者退到不嵌入的方式 —— 没有第三条。要嵌入，就在对方站点那边改策略。
诊断只读产品自己看得见的证据（响应头原文、会话日志、配置）
X-Frame-Options 与 frame-ancestors
X-Frame-Options（1999 年的头）只有一个取值来源，能写 DENY 或 SAMEORIGIN，不能列域名白名单。
frame-ancestors 是 CSP 里的指令，可以写具体域名列表，粒度更细；两个都在时按 CSP 走。
对我们的区别只有一条：都判「不可内嵌」。差别只在对方站点能不能用域名白名单单独放行 Pi。
这一张在定什么：
  • 四档是同一根轴，不是四个开关。区别在「模型怎么拿到」：系统提示里整段写（direct）· 只给一行签名、脚本里现查 （codemode）· 用时才拉 schema（deferred）· 根本不告知（hidden）。所以每张卡都必须同时给 怎么拿 / 花多少 / 什么时候用三行，少一行就还是四个英文词。
  • 成本要写成 token 数（direct 约 240/工具、codemode 约 12/工具、deferred 与 hidden 进表时 0）。 「会不会占上下文」这种话用户没法据此做决定；给数字他就能算出该不该动。
  • 改曝光不改连接。服务器照常握手、凭据照常有效，只是下一轮工具表里换一批名字；当前轮已经拿到的提示不变 —— 这一句必须写在界面上，否则用户会以为设置没生效又去改一遍。
  • 「调用次数」只统计真发出去的调用，模型幻觉出来的工具名不进账。否则这一列会反过来教用户「这个工具很有用」， 而它其实一次都没被真正调过。
  • 策略头只解释不绕。x-frame-options 与 frame-ancestors 是站点所有者 表达的防点击劫持策略，客户端能做的只有「说明原因」或「退到不嵌入的方式」，不提供任何绕过开关。 这条写在横幅里而不是藏在文档里：它是设计决定，不是暂缺功能。

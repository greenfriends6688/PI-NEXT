为什么定位成「降级形态」
模拟器的价值在行为（真渲染管线、真权限、真生命周期），视口外壳的价值在布局（断点、栅格、安全区、横向溢出）。两者不能互相顶替，所以这一层不假装自己是模拟器：它只承诺布局层面的确定结果。
页面里所有模拟器相关入口在纯浏览器形态下隐藏而不是报错 —— 降级要安静。
桌面形态有 electron/ 壳与 bash 工具：能起子进程，因此技术上可以挂一个可选技能。 可装技能

升级路径（按这个顺序做，每步都能单独上线）
视口外壳进产品：机型预设 + 横竖 + 取景缩放 + 截图

进 CI：无 SDK 的机器只跑视口那一档，作为布局回归
这一张在定什么：
  • 先把定位钉死：这一层是视口外壳，不是模拟器。ZCode 的 ios-simulator / android-emulator 走 xcrun simctl 与 adb，插件本体不在本仓，依赖本机装了 Xcode / Android SDK。
  • 本仓的现状决定了形态：桌面形态有 electron/ 壳与 bash 工具，能起子进程 → 技术上可做可选技能；纯浏览器形态没有子进程 → 这一形态只画到视口为止，入口隐藏而不是报错。
  • 机型预设真换机：五档预设换的是逻辑视口（宽 / 高 / DPR / 安全区），不是换一张图；取景缩放只是把它画小，CSS 缩放不触发断点重排，所以「手机断点生不生效」只看底栏那行数字。
  • 一块内容两块视口：PWA 画板与产品页是同一套产物的两个入口，预览器负责切换，不给两套配置项。
  • 截图的边界要写明：纯 Web 只能截视口 DOM，截不到状态栏、灵动岛与控制中心 —— 那三样只有真模拟器或真机给得了。
  • 升级路径分五步：视口外壳 → 桌面探测 SDK → 挂模拟器技能 → 并排对照 → 进 CI 做布局回归。每步都能单独上线，卡住也不影响前面。

D-30 · 键盘与焦点

前两张规格台管「动得对不对」，这一张管「不用鼠标能不能用」。四条纪律： 焦点环必须有（--nx-focus-w / --nx-ring，现在只有输入框有）、Tab 序就是阅读序 （长列表与页签组走 roving tabindex，不许让 Tab 走到天亮）、Esc 一次只关一层 （浮层 → 抽屉 → 弹窗 → 退出输入态，顺序不能反）、减弱动效停终态（下面第四帧逐条写清停在哪一态）。 四帧都可以真按：Tab、方向键、Esc、开关都接着真行为。

焦点环 · 提案用 :focus-visible，不用 :focus（点鼠标不该出环）
/* 环宽 1.5px（--nx-focus-w），颜色 --nx-ring；只在可点件上画。 outline 走 outline-offset:2px，不改布局，也不会被父级 overflow:hidden 裁掉。 */ :where(button, a, input, textarea, select, [tabindex]):focus-visible { outline: var(--nx-focus-w) solid var(--nx-ring); outline-offset: 2px; } /* 深色下环已经换过变量（--nx-ring），这里只补 offset，不另写颜色 */ [data-theme="dark"] :where(button, a, [tabindex]):focus-visible { outline-offset: 2px; } /* 减弱动效：环仍然必须出现（它是信息，不是动效） */ @media (prefers-reduced-motion: reduce) { :where(button, a, input, textarea, select, [tabindex]):focus-visible { outline: var(--nx-focus-w) solid var(--nx-ring); } }
用 :where() 把优先级压到 0，所以 .d-input 现有的 :focus 规则仍然生效（输入框点击也要出环）。 环的「出现」不许做成淡入动画 —— 减弱动效的用户必须在 1ms 内看见它（见帧 D）。

顺序是后开的在上：浮层永远压在抽屉上，弹窗压在浮层上。 三条硬规矩：① 一次只关一层（连按会一层层退，不许「一下全关」）； ② 关掉后焦点要回去（关浮层回触发钮，关弹窗回弹窗前的那个控件）； ③ 到底了要有反馈（在底层按 Esc 不许什么都不发生，Toast 说一句「已是最上层」或者干脆不响应，但不许闪烁）。
Esc 不许用来「撤销上一步」：撤销是 ⌘Z 的活。 Esc 是「退出当前上下文」，语义不同 —— 混用会让用户不敢按。

判据只有一条：减弱之后信息还在吗？ 流光没了，但「在加载」这句话还在； 骨架不扫了，但形状与位置还在；翻卡不翻了，但新值直接在了。 凡是要靠动画结束才读得出来的信息，都是动画在替界面说话，必须补一条静态表达。
这一张在定什么：
  • 焦点环用 :focus-visible，不用 :focus：点鼠标不该冒环，Tab 走过去必须冒。环宽与颜色只取 --nx-focus-w / --nx-ring，不给组件各画一次。
  • Tab 序 = 阅读序：页签组与长列表走 roving tabindex（组只占一个停靠点），纯说明文字用 tabindex="-1" 跳过，disabled 不进。
  • Esc 一次只关一层（帧 C）：浮层 → 抽屉 → 弹窗 → 退出输入态；关掉后焦点必须回到触发它的那个控件。
  • 同一组键不许有两种意思（帧 D）：冲突按「就近原则」裁决，并在帮助页与改键处都写出来。
  • 减弱动效一律停终态：base.css 与 system.css 的 reduce 块已经兜住了时长，本帧逐条写清「停在哪一态」，判据是「停完之后信息还在吗」。
  • 焦点环已落库：按钮 / 页签 / 行 / 浮层项统一走一条 :focus-visible 规则（写成就用 :where() 把优先级压到 0，不与各控件自己的 :focus 打架）；之前**只有输入框与文本域有描边**，Tab 走过一帧看不出焦点在哪 —— 那是无障碍缺口，不是风格问题。

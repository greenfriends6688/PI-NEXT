为什么不用浏览器原生查找：它数不到分页窗口之外的命中、走不到「加载更早」那段历史， 而且每条消息都做了记忆化，原生的选中模型会和它打架。Enter 下一个 · Shift+Enter 上一个 · Esc 关闭（且不打断正在跑的回合）。
这一张在定什么：
  • 审批的三档是等权重的：「允许一次 / 本会话允许 / 永远拒绝」是同一层的三个选择，所以没有主按钮、没有危险色 —— 一旦把「允许一次」做成实心主按钮，用户会把它当成「确认」顺手点掉，那正是最不该被顺手点掉的一档。
  • 只有「本会话允许」会写会话：授权存进 pi-web:tool-grants custom entry，随分支回退一起回退；「允许一次」什么都不写，避免会话文件堆噪音。超时不答、点停止、关对话框一律按拒绝处理。
  • 压缩是单行提示 + 事后一条记录：进行中只在输入框那一行给「正在压缩…」并把相位文案从「等模型」压过去（不压的话它读起来像挂死）；完成后转录里才出现一条 compaction 记录，带摘要与文件上下文。失败态给的是服务端原文加一个重试。
  • 七个 stopReason 一个都不能少，也一个都不能只写机器词：stop 正常、toolUse 表示还没结束、length 是被输出上限截断（要提示「发追问可以继续」）、deferred 交给后台、aborted 是你点的停止、pending 还在跑（流式中不画这一行）、error 是失败。
  • 「等你处理」有两个位置：转录里那条待回答对话框（收起态就是停在输入框上方的一行，带倒计时条），以及侧栏会话行上的「待授权 / 待输入」标记。两者都只在会话挂起时出现，都不弹模态。
  • 不打断的提示一律不做成模态：加载骨架、未读计数、通知三色都只是行。通知只报已经发生的事，唯一允许的动作是撤销 / 重试 / 跳转 —— 要用户做决定的，去模态。

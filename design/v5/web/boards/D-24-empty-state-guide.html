历史里为什么不存会话全文
全存会让工作流目录长到几千 MB，而且换台机器就对不上号。这里只存 参数 + 结果 + 耗时 + 结论；要看某次的具体过程，从结论跳回那次会话。

本项目：.pi/workflows/ 全局：~/.pi/workflows/ 跟着 git 走的是项目里的那份
格式是给人看的：参数与步骤都用最少的行，谁改了什么一眼能 diff。
改这份文件会发生什么
语法先过一遍：参数缺 type 或步骤缺 id，直接报行号不落盘即时
改参数不动历史：历史是既成事实，只记不改不追溯
改步骤按前缀匹配：id 变了才重跑，没变的步骤直接复用上次结果下次运行生效
删掉一个步骤：在下一次运行前的确认里点名，不静默消失运行前确认
项目里的那份跟着 git 走：谁改了它，diff 里一眼能看出来；全局那份只在本机，不进任何仓库。
这一张在定什么：
  • 引导 6 步，每步只问一件事：欢迎 → 选工作区 → 配模型与 API Key → 选默认工具档 → 手机扫码 → 完成。前 4 步决定「能不能开工」，第 5 步是可选入口，第 6 步只做确认。
  • 进度写在一根轨上（.d-plan-rail + .d-plan-dot）：完成是划线灰、当前是高亮点、没走到是空点 —— 用户随时知道「还剩几步、我卡在哪」。
  • 跳过的步骤必须被点名，不能悄悄消失：第 6 步把「手机扫码：已跳过」列出来，它随后变成顶栏的一行提示，点一下就能补。
  • Key 与权限这两步要敢写清边界：Key 只落本机钥匙串、发请求时代填、导出时替换成占位符；工具档默认「外发关闭」，并写明「关着不是缺陷」。
  • 工作流的参数是它的一部分（.d-field / .d-select / .d-switch）：填一次存下来，「用上次的参数」一键回填；历史只留参数与结果，不存会话全文，否则换台机器就对不上号。
  • 提升为全局 = 步骤全局，不是机器全局：全局工作流在所有工作区可见，但运行时仍在当前目录里跑；列表按项目分组，跨项目的那两份带「全局」标记，一键能收回成本项目私货。

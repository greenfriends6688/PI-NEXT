D-12 · 设置 · 子代理（总开关 · profile · 工具白名单 · ext:）

子代理是「另起一个模型，让它自己跑完一件事再回来」。它贵、它会自己拿工具，所以这一节的核心不是功能而是 边界：什么时候开、开哪些工具、一次最多几轮、名字怎么解析。 内置子代理总开关默认关，而且切换后必须重载会话才生效 —— 系统提示已经在会话开头发出去了， 中途改总开关只会造成「配置说开了、这一轮却没有子代理可用」的错觉，所以开关旁直接写明这一条。

创建后 ext 能被解析到，但工具列表是空的 —— profile 引用它之前不会调得到任何东西。
这一张在定什么：
  • 总开关默认关，且切换后必须重载会话。系统提示在会话开头一次性发出，中途改只对下一轮生效 —— 面板把「需重载会话」标在开关旁边，而不是让用户以为已经生效了。
  • 白名单是默认拒绝，不是默认放行后拦截。没勾的工具不在子代理的提示词里；越权默认报错并中止，可改成「转交主会话批准」， 但批准框里写的是子代理的意图，不是原始参数。
  • shell 单独提示。它和 read 并列在一堆芯片里会被当成「又一个开关」勾掉，所以它在芯片区外单独一条警告。
  • profile 一行给全五项。名称 / 描述 / 模型 / 思考 / max turns 挤成一列就要横向滚；派出去之前想「它会用什么模型、能不能写盘」的人不会去点开。
  • ext: 的解析顺序写死并逐条展示结果。插件 → 用户目录 → 项目目录，命中即停、同名标注实际用的是哪一处； 三处都没有就报错并中止，不猜名字、不静默降级 —— 降级等于把机器敞开而用户毫不知情。
  • 新建扩展只建目录与声明，不生成可执行代码。「名字先占住」比「跑不通的扩展」安全。

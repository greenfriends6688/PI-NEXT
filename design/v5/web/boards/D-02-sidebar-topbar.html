项目多了以后侧栏怎么排？按项目分组还是按时间倒序？
PI NEXT 已定

按项目分组，组内新的在前、置顶在最前。理由是「我在哪个仓库干活」 比「我什么时候干活」更能预测下一步动作；组头显示条数，折叠后项目还在， 不会因为滚下去就以为丢了。项目行的动作（打开文件夹 / 重命名 / 归档 / 移除）挂在行尾 ⋯。

描述任务，或 @ 提文件、/ 提命令
这一张在定什么：
  • 侧栏是「上下文清单」，不是导航树：品牌行（logo · 搜索 · 折叠）→ 新建任务（⌘N）→「项目 / 聊天」双分段（两个不同的项目键，不是过滤）→ 项目分组树 → 底栏（手机与推送 · 版本徽章 · 设置）。没有时间分组、没有过滤页签、没有分页。
  • 搜索格只在搜索态出现：默认态侧栏里没有搜索格（帧 A / 帧 C）；点品牌行那枚放大镜才展开并聚焦（帧 D 是搜索态），placeholder 固定「搜索所有对话…」。清空钮 = 关闭搜索，不只是清文字，Esc 同义 —— 常显的搜索格会让「默认」和「搜索中」在界面上不可分，还白占一行高度。
  • 折叠不等于删除：导轨（48px）只有三枚——拉回侧栏 / 搜索 / 新建任务，点哪一枚都会把侧栏带回来，搜索还会直接聚焦搜索框（帧 B）。
  • 项目行自带动作：行尾 hover 出 ⋯（打开文件夹 / 重命名 / 归档或恢复 / 从列表移除）与 ⊕（在该项目里新建会话）；选中项目展开时，worktree 切换行嵌在它下面（细节见 D-02d）。
  • 顶栏左端是「身份两行」：标题 + 运行中芯片 + 分支芯片（分支芯片可点，是 worktree 列表），副行是「项目 · 上下文 %」。会话改名后两行同时跟着变。
  • 右端动作是产品真实那一排：完整历史 / 生成标题 / 子代理（仅有子代理时出现）/ 分支导航 / 导出 Markdown / ⋯；最右另有工作区对调与右栏开关。低频诊断（系统提示词 / 工具定义）收在 ⋯ 里（帧 C）。
  • 浮层里不放我们没做的动作：每一条都必须当场生效；没有「历史版本」「定时任务」「只看未读」「分页」这些产品没有的东西。

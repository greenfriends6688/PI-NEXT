即时生效的三条纪律
不给「保存」这一分节的改动全部即时落盘，弹窗脚的说明写的是状态而不是按钮
数值设置配「重置」已经是默认值时重置钮禁用，且 title 写「已经是默认值」而不是功能名
关掉设置回到原处改完壁纸立刻回到转录，不把人留在设置里找「在哪保存」
这一张在定什么：
  • 宿主是设置弹窗，不是整页。三帧都是 .d-modal.is-open + .d-modal-box.wide + .d-set，内容与 D-07 的弹窗宿主同一份；弹窗限高、内容区内部滚动，所以长分节不会被视口裁掉。
  • 壁纸块紧跟在主题皮肤块正下方。两者在抢同一件事（谁管背景），分开放要来回扫视。块内四行：显示壁纸（关掉时遮罩浓度与各面适配整块消失）、当前壁纸（缩略图 + 选择/更换/移除，没图时只有「选择图片」）、遮罩浓度、各面适配（消息区 / 侧栏面板 / 输入框 × 不透明 / 半透明 / 毛玻璃）。
  • 三个面用芯片排而不是下拉。只有三档，下拉把另外两档折进一个箭头里，读者要在脑子里做三次数组查询才比得出。墙纸铺满一切会让输入框与代码块读不清 —— 每个面自己选一档。
  • 内置画廊是行内的一段，不叠模态。每次选择都要立刻反映到左边的实时预览上；套一层带「应用」的模态会把这条例约反过来，还要处理焦点陷阱套焦点陷阱。画廊与皮肤工作室共用同一份列表。
  • 有皮肤生效时整块收成一句话。壁纸与各面透明度被皮肤接管，此时一排滑块就是「看着能调、其实无效」的死控件 —— 只给说明与「编辑主题皮肤」。
  • 侧栏只有两行：半透明（与壁纸是同一件事的两个旋钮）+ 宽度滑块。宽度只改轨道，不改正文列排版宽度。
  • 界面字体三行：UI 字体 / UI 字号 / 界面语言。UI 字体清单是本机枚举的：先试 Local Font Access API（Chromium，要授权且必须在手势里），空了再用 canvas 宽度探测；等宽族被过滤掉。字号给档位不给连续滑块 —— 连续值会停在规范里没有的那几档上。
  • 聊天块 11 行：自动命名 / 命名模型 / 默认展开思考块 / 界面密度 / 过程步骤默认展开（推理 / 命令 / 工具调用 = 三个独立开关，不是一个单选组） / 聊天内容宽度（滑块 + 重置）/ 聊天字体大小 / 扩展组件字体大小 / 选中文字提问浮窗 / 发送键。最后三行是同一件事的三粒旋钮：正文、第三方组件、发送行为各管各的。
  • 通知块 7 行：桌面通知（总开关）/ 任务完成 / 任务失败 / 仅在窗口未聚焦 / 通知声音 / 两个动作钮（发送测试通知 · 打开系统通知设置）。总开关关时四个子项是禁用态而不是各自清零；测试通知发真的通知，失败那一条原样带原因。
  • Shell 工具整块只在 Windows 渲染。macOS / Linux 连标题都不出现 —— 一行永远为假的开关是噪音。与「暂停」是两回事：暂停的行还显示自己的状态徽章与一个说清原因的 title。

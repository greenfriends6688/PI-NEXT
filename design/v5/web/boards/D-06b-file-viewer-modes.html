菜单为什么随状态变
因为每个动作的前置条件不同。与其给一颗点不动的按钮加一句「暂不可用」，不如在不该出现的时候不出现；真被问到了，再在提示里说清为什么。
没有版本可比时不渲染
没有未保存时不渲染
编辑中禁用 + 说清
这一张在定什么：
  • 可编辑源码的三态：未保存（头部多一枚徽章 + 撤销 + 带 ⌘S 的保存）、保存失败（内容保留在编辑器里，原地给一次重试）、冲突（不做自动合并，两块并排各带各的动作）。 正文区与只读源码完全一样 —— 编辑态不是另一个查看器。
  • 「与 HEAD 对比」是一个覆盖层，不是一个模式。它排在模式切换旁边；开起来整个内容区换成只读 diff，顶部一条横幅写明在看什么并给「返回源码」；关掉回到原视图，不丢滚动位置、不重开标签。
  • 文件已从磁盘删除不能给空白面板。对比开着就给删除说明 + 与 HEAD 的差异；对比关掉给一条 role="status" 的说明，头部仍保留对比入口 —— 那是删除后唯一可用的视图。
  • frontmatter 单独成卡。标题与标签有语义（给人看的），键值表原样回显；布尔值给徽章。改的是呈现不是文件，保存时写回的还是原来那份 YAML。正文照常 Markdown 渲染。
  • CSV / TSV 走真表格：首列行号、数字列等宽右对齐、宽表横向滚动（不压字）、超窗口出行数条。分隔符嗅探在解析层，不在视图层。
  • 图片的工具栏只有四样：缩放百分比（点回 100%）/ 放大 / 缩小 / 适应窗口与 1:1。拖拽平移不给按钮；缩放值写在工具栏上而不是盖一层浮层。
  • 滚动淡出用上下两条渐隐，pointer-events: none，只在真能滚时出现 —— 它是指示不是装饰。
  • 音视频共用一条规律：播放控件自己就是全部。没有缩放、没有行号、没有「返回源码」；面包屑、下载与 live / static 圆点照常，因为它们与播放无关。
  • 三种 iframe 三种权限，写在板面上：HTML 沙箱 allow-scripts（刻意不给 allow-same-origin）· PDF 不加沙箱 · docx allow-same-origin（为了读 iframe 内的选区，代价是引用退回路径快照）。 PDF 的页码与缩放都走 URL fragment（#page=3），所以能分享、能后退；缩放步进走按钮不走滚轮。
  • 打不开永远带替代路径。二进制说清「没有内置渲染器」，未知扩展名先给一次按文本读的机会；两者都给「在文件管理器中显示」与「用默认应用打开」，并且保留一条可复制路径。
  • 动作菜单四态，壳一样项不一样。普通文本 / 二进制 / 已删除 / 有未保存 —— 动作的前置条件不同，所以不该出现的时候就不出现；真要保留（比如编辑中禁用外部打开），就在提示里说清为什么。
  • 十个分支，一个外壳。面包屑与动作行永远在原位，切换分支不换位置。

D-26 · 对话框与系统态（模态 / Toast / 横幅 / 空 / 载 / 错）

系统态是「没人设计过、但天天遇到」的那部分，所以只定三条纪律： 能中断的才用模态（不可逆或要离开当前上下文才弹）、Toast 只报已经发生的事（没有按钮、不预告、不追问）、 失败必须带下一步 —— 错误码 + 原因 + 一条真能按的按钮。空态和骨架不算「失败」， 但也不能装作在加载：骨架旁边永远有一句「正在做什么」。

这一张在定什么：
  • 能中断才用模态。不可逆、或用户必须离开当前上下文才能继续的，才弹模态；其余一律就地解决。危险确认：标题写清作用对象，两个按钮 = 取消 / 删除（危险色），不写「确定」——动词要能被复述。
  • 等待中不给「取消」。只给进度和「放到后台跑」；Esc 也不关（关掉就丢掉了正在做的事）。骨架旁边永远有一句「正在读什么」。
  • Toast 只报已经发生的。没有按钮、不提问，固定 4 秒自退（两端同一个值）；要用户决定的，去横幅或模态。
  • 横幅 = 需要你做点什么：可关闭、可带一个行动按钮，三态（信息 / 警告 / 错误）只改语义色与边框，不换布局。
  • 三种「现在没有 / 现在做不到」分开处理：空态给下一步（换说法、重建索引、看最相关的文件）；骨架给进度与可重播；错误给原因 + 可复制的下一步 + 重试，并且明说「重试不会自己变好」。
  • 项目信任不是一道门，是三档：信任一次 / 本次会话信任 / 永不信任。未信任时把人挡在门外是错的做法 —— 正确做法是把写文件与执行命令降级为逐次点头，并把「目录里有什么、信任之后会发生什么」在弹窗里逐条讲清。

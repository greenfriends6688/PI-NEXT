行内提及

把 design/v5/base.css 里的比例令牌改名，再在 check-v5 里加一条门禁。

这一张在定什么：
  • 用户消息的两个危险动作必须分色：「从此处编辑 / 新会话」不动原文（开分支），所以它们是普通按钮；「回退到此处」会删掉后面的轮次，所以警告条只挂在它下面，文字用产品里那句确认原文（「已经写到磁盘的文件不会被回退」）。把两者都写成「编辑」是最容易出事的一种含糊。
  • 代码块的头只有两件东西：语言标签与复制。复制是三态而不是两态 —— 剪贴板可能被拒，失败必须看得见（按钮转红 + 一枚 bad 徽标），否则用户拿着空剪贴板以为复制成功了。超大块跳过高亮时仍然铺开代码本身，只在头里多一句原因。
  • 附件不给统一预览器：图片走灯箱、PDF 走内置阅读器（正文里的 #page= 带页码）、DOCX 转文本、音频给波形条、视频给内置播放器、文本等宽只读，其余一律「无法预览 + 下载」。留一块空白让人猜是最差的一种处理。
  • Mermaid 的三态是一条降级链：图形态（默认）→ 源码态（点「源代码」）→ 渲染失败（退化成源码 + 一行原因 + 重试）。失败态绝不吞内容，也不给一块空白画布。全屏查看器是 <dialog> 真模态，Esc / 点遮罩 / × 三种关法，与图片灯箱一致。
  • 公式的类名必须留：.d-math 只是外框（等宽 + 代码底色），KaTeX 的 katex / katex-display 一个都不能去掉 —— 它的 CSS 里有几百条后代选择器靠这两个根类名。去掉的后果不是「丑一点」，是整套数学排版散架。

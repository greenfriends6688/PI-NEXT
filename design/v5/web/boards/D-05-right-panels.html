轨迹页签记的就是这一串：读了什么、跑了什么、写了什么 —— Git 面板只是它的一个视图。
Git 面板只做三件事
看图谱（谁在哪条线上）、看改动（与工作区的 diff）、看远端（fetch / push 状态）。不代替命令行。
这一张在定什么：
  • 五个常驻页签 + 一颗单例轨迹页签。轨迹排在最左、只出现一颗：文件、终端、浏览器、Git、审查的动作全部汇进同一条线，不按面板各开一份。「agent 刚才动了什么」永远只有一个地方看。
  • 审查只读，两份来源分开列。上面是工作区改动（git diff 的逐文件清单：已修改 / 未添加 / 未跟踪 + 增删行数），下面是本轮 agent 写过的文件（来自会话：刚写入 / N 步之前）。口径不同所以不合并成一张表；也不给 Keep / Reject —— 处置改动留在 Git 页签与命令行。
  • 点已选中的页签 = 打开这一栏的总览。再点一次不会切走、也不会没反应，而是把页签清单、面板动作、关闭入口摊开（所以每个演示帧的当前页签都挂了一个真能点开的浮层）。
  • 浏览器三态是本仓此前的缺口。跨站：常驻提示条说清「已经离开本地」并给一个回到本地的动作；加载失败：给错误码 + 怎么把它变成命令，而不是干等；被 CSP / X-Frame-Options 拦截：明确写出这是站点自己的策略、我们无法绕过，然后给两条能走的路。三态都不做无意义的自动重试。
  • 终端不吞失败。被权限拦下的命令留在原地并说明原因；页脚永远写清「在哪个分支、跑了多久、什么编码」，让人敢把 agent 的命令当成自己的命令看待。
  • Git 面板克制。只做「看图谱 / 看改动 / 看远端」三件事；会改写历史的操作（rebase、cherry-pick）不提供按钮，必须自己敲。泳道用 .d-git-lane + lucide 图标，不画一根自己的 SVG 线。

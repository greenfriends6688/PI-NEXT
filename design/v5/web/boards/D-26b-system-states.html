主路径 · 交给系统 本机首选
本机跑的时候根本不弹自家窗口：点「选择目录」直接拉起操作系统的文件夹选框（macOS choose folder · Windows FolderBrowserDialog · Linux zenity / kdialog）。系统对话框本身不画 —— 那是操作系统的东西，不归我们设计。
步做什么结果
1POST /api/cwd/pick拉起系统原生选框
2返回 cwd直接采用，不弹任何自家 UI
3返回 cancelled什么也不做（用户自己取消的，不追问）
4返回 501 fallback 或请求失败退到右边的自绘浏览器
触发回退的三种真实情况：浏览器直连本机地址（远程访问）、服务器上没有显示器、Linux 机器上没装 zenity / kdialog。

为什么主路径是系统选框
自绘浏览器能做到系统选框做不到的事：输入路径、新建文件夹、重命名、删除。所以它不是替代品，是补充 —— 能用系统能力时用系统能力（它有系统级的权限申请、iCloud 位置、最近使用与拖放），拿不到时才自绘。 反过来做，用户会先在你的列表里被授权一次、再被系统问一次。

这一张在定什么：
  • 目录选择的主路径是系统原生选框，自绘浏览器只是回退。决策链固定四步：POST /api/cwd/pick → 返回 cwd 直接采用 → 返回 cancelled 什么也不做 → 501 fallback 或请求失败才退到自绘。系统对话框本身不画。
  • 自绘浏览器的五种状态都是行内切换。浏览中 / 新建文件夹 / 盘符（Windows 驱动器列表）/ 删除确认（长在那一行上，不弹第二个模态）/ 路径已改未提交。 最后一种的纪律是：不可点的按钮必须在 title 里说清为什么（「选择前请先打开此路径」），不能写功能名。
  • 应用级错误页分两级，样式来源不同。段级（app/error.tsx）走完整主题 token，可重试并暴露 digest；根级（app/global-error.tsx）必须自己渲染 html/body，没有 data-theme，只用系统色 Canvas / CanvasText。 两级都给「重试」，因为用户此刻唯一能做的事就是再试一次。
  • 拖放只有三态，规则先于视觉。可接受（强调虚线 + 强调淡底）、拒绝（换禁止图标并写明原因，1.2 秒自动退回）、拖到输入框（只有输入框变，落点更精确）。 四条规则写死：图片→附件芯片；其它文件与目录→@ 路径引用；超 20 MB 图片→降级不报错；非文件内容→拒绝。
  • 扩展请求四种类型共用一个壳。选择 / 确认 / 输入 / 编辑器（已响应时收成只读回显，不再给按钮）。倒计时条是扩展自己的等待窗口，归零后按默认值继续，不阻塞会话 —— 所以它给的是进度条加秒数，而不是一个逼你点掉的弹窗。输入型请求不给倒计时。
  • 附件预览只有一个壳，图片是它的满宽变体（不加边框，加了就像被框住）；加载 / 失败 / 不支持三种都在壳内就地显示，不换通知条 —— 通知条会自己消失。
  • 项目信任三态是同一个模态的三种头部图标（盾牌问号 / 转圈 / 叉），不是三个组件；三个选项从窄到宽：信任一次 / 本次会话信任 / 永不信任；失败态必须给可执行的下一步（换目录或重试），不给「确定」。
  • worktree 行在项目行之下、会话行之上，切换器是抽屉不是新页面（切检出是原地换上下文）。移除检出的三态：干净→一句确认；有未提交→先报数量，再走危险确认（标题写清 worktree 名，按钮 = 取消 / 删除）；正在使用→不给移除。
  • 这一整张板没有一条左边线。层级一律靠底色、徽章、圆点与图标表达 —— 这也是门禁 check-v5 逐张板强制的那条。

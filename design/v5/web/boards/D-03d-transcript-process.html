这条结论有用吗
父子层级靠缩进与图标表达，不用左侧竖线：子代理的卡本身就是工具卡的一种， 它的工具调用在父卡内部再排一层步骤流，读者一眼能分清「它做的」和「这条回合做的」。
这一张在定什么：
  • 过程只有一条时间轴。一轮内的工具调用收成一条竖线串起的步骤流，汇总行给「N 个文件 · M 条命令 · K 次工具调用 · J 次失败 · L 段思考」。竖线在首行从图标中心起画、末行到中心收笔 —— 中间连、两头断，这是竖线唯一合理的收法。
  • 失败就地标红，不另开卡：图标与动词进 error、右侧挂一枚「失败」徽标，语义动词与目标文件全部保留（否则整行读作「bash 39s 失败」，既不知道跑了什么也不知道动了哪个文件）。要看详情才展开成工具卡。
  • 失败不整卡着色：只换两处 —— 状态图标转 error、输出底色转 error 底。边框永远是发丝线，不加左侧彩条。整卡描红会让「哪一步失败」淹没在一片红里。
  • diff 三视图只有排布不同：行内、分栏、对比上一次提交共用同一份词级高亮。全部只读 —— 本应用没有 Keep / Reject 审阅条，改动由 agent 自己落盘，所以任何「保留这一段」的按钮都是假的。
  • 三种「不是普通工具调用」的形态各有宿主页：嵌入式终端卡复用工具卡（所以你自己敲的命令和 agent 敲的长得一样）、codemode 的脚本调用是卡内的行、 子代理的工具行缩进一级并配一枚「打开子代理会话」。

这一张在定什么：
  • 轨道与时间线不同时常驻。轨道回答「还剩几步、卡在哪」，时间线回答「这一步慢在哪、错在哪」； 任何一步超过 2 分钟或失败，卡片自动切到时间线。两套同屏会让人开始改错那一份。
  • 失败详情挂在时间线上，默认展开。轨道是给人看状态的，三行堆栈塞进去就把状态盖没了； 而「失败了还要再点一次才看到为什么」会被当成卡片没做完。
  • 队列只有两态，两态都能恢复。自动接续＝回合一结束就发下一条；已暂停＝原样留着不自动发。 恢复方式一次写在浮层里：从失败处重试 / 从这条继续 / 丢弃并重来，外加一条红色的「全部丢弃」。 出了这个浮层没有别的入口 —— 恢复方式不能靠记忆。
  • steer 靠底色 + 徽章表达，不用竖线。.d-queue-row.steer 给一块极浅的暖底，行内再给一枚 warn 徽章写清「打断当前回合并插到最前」，行首是 .d-grip 图标。 层级在这套体系里一律靠底色 / 徽章 / 圆点 / 图标，竖线已整体废止。
  • 插槽是位置不是样式。8 个 slot 每行写清三件事：由谁渲染（扩展渲染 / 宿主排版）、能否被用户关掉（一列真开关）、 撞车怎么办（先到先得 / 排队 / 拒绝 / 确认后替换）。扩展拿不到宿主类名与内部状态，产品改命名时扩展不必跟着改。
  • 只有 chat.composer.top 能整块替换且须用户确认； app.overlay 同一时刻只允许一个，后来者排队不覆盖 —— 两个全屏浮层叠着，用户关不掉。
  • 帧 D 的虚线框是画板家具（.d-slotoverlay），产品里没有这圈虚线；它的作用是让人一眼看到插槽落在哪，而不是加一个装饰。

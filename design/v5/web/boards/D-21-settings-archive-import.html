这一张在定什么：
  • 四种「东西不见了」的口径必须分开写。 归档＝标志位（archived / archivedAt，本机、跨标签页同步），恢复＝取消归档，永远不依赖页面还能不能打开； 彻底删除才删 .jsonl，要二次确认。导入＝两段式（/api/import/scan 只读扫描 → 勾选候选 → 试运行 → /api/import/apply 落盘），界面只送候选 id，服务端重扫反查，注入不出路径； 快捷键只读地图＝只展示此刻真正生效的键位（可编辑键位表已下线）；记忆为空＝什么都不注入，绝不塞占位空段。
  • 危险动作的默认值要替用户踩刹车。批量条只在有选中时出现（一条都没选时整条不出现，而不是灰着摆在那儿）， 「永久删除」永远二次确认：标题写清对象（选中的 N 条归档会话），两个按钮是取消 / 删除（危险色），正文写清删的是文件本身； 「确认导入」在没试运行之前是 disabled。归档页最容易出的事不是删错一条，是手滑删一片。
  • 试运行不发请求。三段数（将导入 / 将跳过 / 将失败）在本地算出来给你看，代价是「预估」两个字必须写在数字旁边； 真正落盘之后仍然是 imported / skipped / failed 三段报，不假装全部成功。
  • 冲突策略默认「跳过」。三档里只有「跳过」是无损的，所以它是默认；「覆盖」那一档用红色横幅写清「不可撤销」，不是一句提示。
  • 快捷键只读地图，不给任何录制入口。可编辑键位表已随产品下线（本轮用户裁定），地图只列出此刻真正生效的绑定： 「命令面板 / 会话内查找」这类由功能自行注册的行显式标「未接入」，历史改过的绑定标「你改过」—— 地图上列出键帽就是在承诺「按了有用」，不标就等于骗人。
  • 两种空态要分开给出口。「还没归档过」教你去归档，「归档过但文件没了」给一个开关； 「记忆为空」给两个动作（手写 / 从计划文档摘）。合成一句「暂无数据」的话，两边用户都无处可去。
  • 命中预览逐字等于实际注入。预览块与真实发送的文本同一份来源（含「超预算未注入」的说明）， 否则用户会以为被砍掉的那条还在生效 —— 那才是真的丢东西。
